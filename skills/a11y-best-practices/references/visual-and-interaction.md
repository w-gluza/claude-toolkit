# Accessibility Visual and Interaction Rules (WCAG 2.2, MDN)

Extracted 2026-11-08 from the w3c/wcag repository and the mdn/content repository. Baseline statuses from the web-features dataset on the same date.

## Text contrast

- **Give body text 4.5:1 and large text 3:1, and never round up**: "18 point text or 14 point bold text is judged to be large enough to require a lower contrast ratio." and "The 3:1 and 4.5:1 contrast ratios referenced in this success criterion are intended to be treated as threshold values. When comparing the computed contrast ratio to the Success Criterion ratio, the computed values should not be rounded (e.g., 4.499:1 would not meet the 4.5:1 threshold)." In CSS pixels large text is roughly 24px regular or 18.5px bold. Why: "The 4.5:1 ratio is used in this success criterion to account for the loss in contrast that results from moderately low visual acuity, congenital or acquired color deficiencies, or the loss of contrast sensitivity that typically accompanies aging." Smell: `color: #999` on a white background for paragraph text (2.8:1), or an 18px regular-weight heading given the 3:1 allowance because it was taken for large text. Source: https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html#intent
- **Hold placeholder, hover and focus text to the same ratio**: "This success criterion applies to text in the page, including placeholder text and text that is shown when a pointer is hovering over an object or when an object has keyboard focus. If any of these are used in a page, the text needs to provide sufficient contrast." Why: "Some people cannot read faint text." Smell: `::placeholder { color: #aaa; }` on a white input (2.3:1), or a tooltip with `color: #767676` on a `#333` background. Source: https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html#intent
- **Only a genuinely inactive control is exempt from contrast**: "User Interface Components that are not available for user interaction (e.g., a disabled control in HTML) are not required to meet contrast requirements. An inactive user interface component is visible but not currently operable." Why: a control that merely looks secondary is still operable, so its label is ordinary text and the exemption does not apply. Smell: `.btn-tertiary { color: #9e9e9e; }` on a white button that has no `disabled` attribute, or "muted" metadata text at 3:1 that users have to read. Source: https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html#inactive-controls
- **Do not let brand colours exempt text**: "Beyond logos and logotypes, text that has insufficient contrast due to corporate identity or brand guidelines is not exempted from the requirements of this criterion." and "If logos normally have sufficient contrast but are presented with an insufficient contrast as an author choice, rather than because of corporate identity or brand guidelines, then that particular low contrast presentation is not exempt from the contrast requirements." Why: the only exemption is the logo itself, as the brand supplies it. Smell: brand yellow `#ffd500` headline text on white, or `.partner-logo { opacity: 0.35; } .partner-logo:hover { opacity: 1; }`. Source: https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html#intent
- **Exceed the ratio for thin or unusual typefaces**: "Due to anti-aliasing, particularly thin or unusual fonts may be rendered by user agents with a much fainter color than the actual text color defined in the underlying CSS." and "authors are encouraged to choose a font with stronger/thicker lines, or to aim for a foreground/background color combination that exceeds the normative requirements of this success criterion." Why: the ratio is checked on the declared colours, so a nominal pass can still be unreadable on screen. Smell: `font-weight: 200` or `300` body text whose colour pair lands at exactly 4.5:1. Source: https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html#intent
- **Reach 7:1, or 4.5:1 for large text, where enhanced contrast is the target**: "The 7:1 and 4.5:1 contrast ratios referenced in this success criterion are intended to be treated as threshold values." Why: "The contrast ratio of 7:1 was chosen for level AAA because it compensated for the loss in contrast sensitivity usually experienced by users with vision loss equivalent to approximately 20/80 vision." Smell: a "high contrast" theme whose body text token stops at `#666` on white (5.7:1). Source: https://www.w3.org/WAI/WCAG22/Understanding/contrast-enhanced.html#intent

## Non-text contrast and colour

- **Give every control and state indicator a 3:1 cue against adjacent colours**: "Unless the control is inactive, any visual information provided that is necessary for a user to identify that a control is present and how to operate it must have a minimum 3:1 contrast ratio with the adjacent colors. Also, any visual information necessary to indicate state, such as whether a component is selected or focused must also ensure that the information used to identify the control in that state has a minimum 3:1 contrast ratio." A control with a visible label needs no border, but a border that is the only cue must pass. Why: "non-text indicators such as the check in a checkbox, or an arrow graphic indicating a menu is selected or open must have sufficient contrast to the adjacent colors." Smell: `input { border: 1px solid #ccc; }` (1.6:1 on white) on an unlabelled search field, `input { border: 0; background: #f5f5f5; }` as the only sign a field exists, or a custom checkbox whose tick is `#e5e5e5` on a white box. Source: https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html#user-interface-components
- **Let hover decorate, never erode contrast**: "additional author-supplied visual treatments for hover are not "required to identify" the hover state." but "The key consideration for any hover effect is that it does not cause a component itself to lose sufficient contrast against adjacent colors, or cause the visual indicators for other states, such as focus or selection, to lose sufficient contrast." Why: the pointer position already announces hover, so the effect is optional while the component must stay visible. Smell: `.btn:hover { background: #fff; border-color: #e0e0e0; }` on a white page, so the button disappears while hovered. Source: https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html#hover-states
- **Give meaning-bearing graphics 3:1 against their background**: "Not every graphical object needs to contrast with its surroundings - only those that are required for a user to understand what the graphic is conveying." For charts: "The lines should have 3:1 contrast against their background, but as there is little overlap with other lines they do not need to contrast with each other or the graduated lines." and "To understand the pie chart you have to discern each slice of the pie chart from the others." Why: a reader with low vision has to be able to find the icon or follow the line without contrast-enhancing software. Smell: icon-only status dots with `fill: #b3b3b3` on white, or adjacent pie slices `#ffd54f` and `#fff176` with no border between them. Source: https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html#graphical-objects
- **Pair every colour-coded meaning with a second cue**: "Use information in addition to color, such as shape or text, to convey meaning." Why: "Not everyone sees colors or sees them the same way." Smell: `.field--error input { border-color: #d32f2f; }` with no icon or message, a chart legend that maps series to colour only, or a status badge that is green or red with identical text. Source: https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html#brief
- **Count a 3:1 lightness difference as a second cue, except for value judgements**: "If content is conveyed through the use of colors that differ not only in their hue, but that also have a significant difference in lightness, then this counts as an additional visual distinction, as long as the difference in relative luminance between the colors leads to a contrast ratio of 3:1 or greater." but "if content relies on the user's ability to accurately perceive or differentiate a particular color an additional visual indicator will be required regardless of the contrast ratio between those colors. For example, knowing whether an outline is green for valid or red for invalid." Why: a light and a dark colour can be told apart without hue perception, but knowing which one means "valid" cannot. Smell: form validation that swaps `outline-color` between `#2e7d32` and `#c62828` with no text or icon. Source: https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html#intent
- **Make inline links differ from body text by more than hue**: "the Working Group regards a link color that meets the 3:1 contrast ratio relative to the non-linked text color as satisfying the Success Criterion 1.4.1 Use of color since it is relying on contrast ratio as well as color (hue) to convey that the text is a link." Why: without an underline, luminance is the only cue left for a reader who cannot see hue. Smell: `p a { text-decoration: none; color: #1a73e8; }` beside `#333` body text (about 1.7:1 between them), or a custom underline below 3:1 against the page while link and body text share a colour. Source: https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html#related-color

## Resizing and reflow

- **Keep everything usable at 200 percent text size, including the steps on the way**: "Content satisfies the success criterion if it can be scaled up to 200% - that is, up to twice the width and height." and "If the resizing mechanism (whether it's provided by the user agent, or implemented by the author) offers incremental resizing steps between 100% and 200%, authors must ensure that there is no loss of content or functionality at these incremental steps." Why: "The author's responsibility is to create web content that does not prevent the user agent from scaling the content effectively." Smell: `<meta name="viewport" content="width=device-width, user-scalable=no, maximum-scale=1">`, or `height: 48px; overflow: hidden;` on a card title that clips at 150 percent. Source: https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html#intent
- **Truncate only when the full text is reachable and signposted**: "truncation is acceptable if the component's full content is available on focus or after user activation and an indication that this information can be accessed, is provided to the user in some way besides the fact that it is truncated." Why: zoomed readers meet truncation first and need a route to the rest. Smell: `white-space: nowrap; overflow: hidden; text-overflow: ellipsis;` on a table cell or nav label with no title, tooltip or expand action. Source: https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html#intent
- **Reflow to a 320 CSS pixel viewport with one-direction scrolling**: "This criterion requires non-excepted sections of content that are written in horizontal languages reflow when narrowed to a width equivalent to 320 CSS pixels." Why: "When lines of text extend beyond the edge of a viewport, users will be forced to scroll back-and-forth to read line by line. This can cause them to lose their place and can significantly increase both physical and cognitive effort." Smell: `.container { min-width: 960px; }`, a `width: 1200px` wrapper, or a grid with fixed `px` tracks and no breakpoint below 1024px. Source: https://www.w3.org/WAI/WCAG22/Understanding/reflow.html#intent
- **Scope two-dimensional exceptions to the element that needs them and cap media at `max-width: 100%`**: "If a section of content meets the exception for two-dimensional scrolling, the exception only applies to that section." and "by presenting the table in its own scrollable container it allows other content which does not meet a two-dimensional layout exception to reflow as its containing element adjusts." For fixed-size media: "By providing the video player a max-width: 100% CSS property, the video fits within the container element. A horizontal scrollbar no longer appears on the page". Why: an unwrapped table or oversized video forces page-level horizontal scrolling that drags the surrounding paragraphs off screen. Smell: a wide `<table>` or `<pre>` placed straight into the flow with no `overflow-x: auto` wrapper, `<video width="1280">`, or `img { width: 800px; }` with no `max-width`. Source: https://www.w3.org/WAI/WCAG22/Understanding/reflow.html#intent
- **Unstick fixed bars at small and zoomed viewports**: "It is strongly suggested that at smaller viewport sizes that such components are modified to have static positioning, or their display can be toggled by the user." Why: "such sticky or fixed content can make reading content difficult if not impossible." Smell: a `position: fixed` toolbar, ad or cookie bar with no media query that returns it to `position: static` and no dismiss control. Source: https://www.w3.org/WAI/WCAG22/Understanding/reflow.html#intent

## Text spacing and orientation

- **Survive the four text-spacing overrides without loss**: "No loss of content or functionality occurs when the following styles are applied:" "Line height (line spacing) to at least 1.5 times the font size", "Spacing following paragraphs to at least 2 times the font size", "Letter spacing (tracking) to at least 0.12 times the font size" and "Word spacing to at least 0.16 times the font size". Why: readers with low vision or dyslexia apply these values through user stylesheets, bookmarklets or extensions, and the page must not fight them. Smell: `line-height: 20px !important`, a fixed `letter-spacing` on components, or no test that applies the four values in dev tools. Source: https://developer.mozilla.org/en-US/docs/Web/Accessibility/Guides/Understanding_WCAG/Perceivable#guideline_1.4_make_it_easier_for_users_to_see_and_hear_content_including_separating_foreground_from_background
- **Never fix the height of a text container**: "Vertical text cut off is a failure." "Horizontal text cut off is a failure." and "Overlapping text is a failure." Why: "Starting from the author's presentation, changing these four style properties to the specified values should not result in a loss of content or functionality." Smell: `h2 { height: 2.5rem; overflow: hidden; }`, `.card__body { max-height: 120px; overflow: hidden; }`, or absolutely positioned captions with fixed `top` offsets that collide when lines grow. Source: https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html#effects-not-allowing
- **Reveal text that only truncates under spacing overrides**: "Where text is not truncated but it is when text is spaced, if there is no mechanism to show the truncated text, it fails this success criterion." Why: "Where ellipses appear as a result of modifying text style properties, the page can still meet the Text Spacing requirements, so long as the content is still available." Smell: a sidebar label at `max-width` that fits by default and ellipsises at 0.12em letter spacing, with nothing shown on focus or activation. Source: https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html#ellipses
- **Do not lock orientation**: "Don't lock content to either portrait or landscape presentation." Why: "Wheelchair users and others may have devices mounted in a fixed orientation." Smell: `screen.orientation.lock("landscape")`, or `@media (orientation: portrait) { .app { display: none; } .rotate-prompt { display: block; } }`. Source: https://www.w3.org/WAI/WCAG22/Understanding/orientation.html#brief

## Hover and focus content

- **Make hover and focus content dismissible without moving the pointer**: "it's important to provide a way for users to dismiss any additional content without the need to move their mouse or keyboard focus, such as pressing the Esc key." Why: "The magnified view generally follows the mouse pointer or keyboard focus, so screen magnification users navigate by moving the mouse or moving the keyboard focus to pan the magnified viewport and display another portion of the screen." Smell: a tooltip or popover component with no `keydown` handler for Escape, where the only way to clear it is to move off the trigger. Source: https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus.html#intent
- **Let the pointer travel onto the revealed content**: "The intent of this condition is to ensure that additional content which may appear on hover of a target may also be hovered itself." Why: "Content which appears on hover can be difficult or impossible to perceive if a user is required to keep their mouse pointer over the trigger." Smell: `pointer-events: none` on the tooltip, a gap between trigger and tooltip, or `onMouseLeave` on the trigger alone hiding the tooltip before the pointer reaches it. Source: https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus.html#intent
- **Keep revealed content until the user removes it**: "The intent of this condition is to ensure users have adequate time to perceive the additional content after it becomes visible." Why: "Users with disabilities may require more time for many reasons, such as to change magnification, move the pointer, or simply to bring the new content into their visual field." Smell: `setTimeout(hideTooltip, 3000)`, or a CSS animation that fades the tooltip out on its own. Source: https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus.html#intent
- **Trigger on focus whatever triggers on hover**: "Content which can be triggered via pointer hover should also be able to be triggered by keyboard focus." Why: keyboard and switch users never hover, so a hover-only reveal is invisible to them. Smell: `.item:hover .tooltip { display: block; }` with no `:focus-visible` or `:focus-within` counterpart. Source: https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus.html#intent

## Focus appearance

- **Show a focus indicator on everything that can take focus, and keep it there**: "Ensure each item receiving focus has a visible indicator." and "The focus indicator must not be time limited: when the keyboard focus is shown, it must remain visible." Why: "Without a focus indicator, sighted keyboard users cannot operate the page." Smell: `:focus { outline: none; }` with no replacement, a reset stylesheet that strips outlines globally, or a focus ring that animates to `opacity: 0` after a delay. Source: https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html#intent
- **Restyle `outline`, do not zero it**: "Assigning `outline` a value of `0` or `none` will remove the browser's default focus style. If an element can be interacted with it must have a visible focus indicator. Provide obvious focus styling if the default focus style is removed." Why: "The outline will be invisible for many elements if its style is not defined. This is because the style defaults to `none`." Smell: `button { outline: none; }` in a component library base, or `*:focus { outline: 0; }` in a reset. Baseline: Widely available (Outlines widely since 2019-10-05; the `outline` entry widely since 2025-09-27). Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/outline#accessibility
- **Scope custom focus styling with `:focus-visible` instead of hiding `:focus`**: "using the `:focus-visible` (instead of the `:focus` pseudo-class) allows authors to change the appearance of the focus indicator without changing when the focus indicator appears." Why: "Changing focus style can decrease usability, while removing focus styles makes keyboard navigation inaccessible for sighted users." Smell: `:focus { outline: none; }` added to stop rings appearing after mouse clicks, instead of `:focus-visible { outline: 2px solid ...; }`. Baseline: Widely available since 2024-09-14. Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Selectors/:focus-visible#focus_vs_focus-visible
- **Give author-styled indicators 3:1 against adjacent colours**: "If the focus indicator is styled by the author, it must meet the 3:1 contrast ratio with adjacent colors." Why: "Even when a control does not need to have a visual boundary indicating its hit area, it will still need to have a sufficiently contrasting focus indication." Smell: `:focus-visible { outline: 2px solid #ccc; }` on white (1.6:1), or a light-blue custom caret as the only focus cue inside a white input. Source: https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html#examples
- **Measure the indicator against the colour it actually sits on**: "Most focus indicators appear outside the component - in that case it needs to contrast with the background that the component is on." and "If the focus indicator changes the border of the component within the visible boundary it must contrast with the component." Why: "Fail: The external yellow indicator (#FFFF00) does not contrast with the white background (#FFF) which the component is on." Smell: `outline-color: #ffff00` on a white page, or `button:focus-visible { border-color: #4b933a; }` on a `#4189b9` button. Source: https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html#related-focus
- **Rely on the browser default only if you touched neither it nor its background**: "this user agent exception can only be met if the author both does not modify the default focus indicator and does not modify its background." Why: "Browser default focus indicators can be made more difficult to see if the author modifies the pixels directly adjacent to the indicator (commonly referred to as its background), such as by positioning a component on top of an image or gradient background, or altering the page's default white background color, for instance using a blue background in combination with a browser's blue default indicator." Smell: `body { background: #1a2b5c; }` or a hero image behind buttons, with no author focus style. Source: https://www.w3.org/WAI/WCAG22/Understanding/focus-appearance.html#exception-default
- **Make the indicator at least a 2 CSS pixel perimeter**: "is at least as large as the area of a 2 CSS pixel thick perimeter of the unfocused component or sub-component" and "Indicators that are inset further within the component (not directly against the component's outer edge) need to be thicker than 2 CSS pixels to meet the minimum size requirement." Why: "Many people can't see small changes in visual appearance, including older people." Smell: `outline: 1px solid`, `outline: 1px dotted`, or `outline: 2px solid; outline-offset: -4px;` (inset, so 2px is no longer enough). Source: https://www.w3.org/WAI/WCAG22/Understanding/focus-appearance.html#minimum-area
- **Change the same pixels by at least 3:1 between unfocused and focused**: "has a contrast ratio of at least 3:1 between the same pixels in the focused and unfocused states" and "If a control receiving focus changes its background (fill color) to a color that contrasts less than 3:1 with the original background, that would not pass the change of contrast." Why: "the greater the change of contrast between states, the easier it is for users to see the focus indicator." Smell: `a:focus-visible { background: #555; }` on a black background, a border that shifts from `#000` to `#444`, or a single-colour outline over a photo or gradient where no one colour contrasts everywhere. Source: https://www.w3.org/WAI/WCAG22/Understanding/focus-appearance.html#change-of-contrast
- **Keep the focused element out from under sticky layers**: "A notification implemented as sticky content, such as a cookie banner, will fail this success criterion if it entirely obscures a component receiving focus. Ways of passing include making the banner modal so the user has to dismiss the banner before navigating through the page, or using scroll padding so the banner does not overlap other content." The enhanced level asks that no part be covered: "Ensure when an item gets keyboard focus, it is fully visible." Why: "Where users cannot see the item with focus, they may not know how to proceed, or may even think the system has become unresponsive." Smell: `position: sticky; top: 0;` header or `position: fixed; bottom: 0;` footer with no `scroll-padding-top` or `scroll-padding-bottom` on `html`, or a non-modal chat panel that stays open while Tab moves behind it. Source: https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html#intent
- **Count dimmed and blurred overlays against the indicator's contrast**: "While the focused item may not be entirely obscured by these overlays, thereby passing this criterion, it may separately fail 1.4.11 Non-text Contrast. In such cases, the focus indicator must be evaluated against the contrast requirements of 1.4.11 while its appearance is affected by the overlays." Why: a half-covered ring under a dark scrim no longer reaches 3:1 even though the element is still technically visible. Smell: a non-modal drawer backdrop of `rgb(0 0 0 / 0.5)` or `backdrop-filter: blur(8px)` over content that remains in the tab order. Source: https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html#intent

## Pointer targets

- **Give targets a solid 24 by 24 CSS pixel square**: "For a target to be "at least 24 by 24 CSS pixels", it must be conceptually possible to draw a solid 24 by 24 CSS pixel square, aligned to the horizontal and vertical axis such that the square is completely within the target (does not extend outside the target's area)." and "The requirement is independent of the zoom factor of the page; when users zoom in, the CSS pixel size of elements does not change." Why: "Some people with physical impairments cannot click small buttons that are close together." Smell: `.icon-btn { width: 16px; height: 16px; }`, a 24px circle with `border-radius: 50%` (its inscribed square is about 17px), or a review comment that says users can pinch-zoom. Source: https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html#size-requirement
- **Space undersized targets so 24 pixel circles do not touch**: "Undersized targets (those less than 24 by 24 CSS pixels) are positioned so that if a 24 CSS pixel diameter circle is centered on the bounding box of each, the circles do not intersect another target or the circle for another undersized target." Why: "sufficient spacing between targets can work as effectively as a larger target size itself." Smell: 20px icon buttons with `gap: 0` (they pass at `gap: 4px`), dropdown items at `line-height: 18px; padding: 0;`, two rows of 16px-tall buttons 1px apart, or a 16px zoom icon overlaid on the corner of an image link. Source: https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html#spacing
- **Keep author-sized scrollbars and native controls clear of content**: "As long as the author has not modified the user agent default size, the target size for a User agent control is excepted." and "If a scrollbar's dimensions have been modified by the author then there must be a passing amount of spacing between the scrollbar and the content of the page." Why: once the author resizes a native control, the exception that protected it is gone. Smell: `::-webkit-scrollbar { width: 6px; }` or `scrollbar-width: thin` on a list whose links run flush to the scroll edge. Source: https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html#exceptions
- **Aim for 44 by 44 CSS pixels on frequent and irreversible actions**: "Make custom targets at least 44 by 44 pixels." Why: "While this criterion defines a minimum target size, it is recommended that larger sizes are used to reduce the possibility of unintentional actions." particularly for controls used often, hard to undo, near a screen edge or inside a sequential task. Smell: `height: 32px` on primary submit and delete buttons in a touch-first app, or 24px icon actions in a mobile list. Source: https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced.html#brief

## Gestures, dragging and input mechanisms

- **Offer a single-point alternative to every swipe, pinch or path gesture**: "Authors must ensure that their content can be operated without multipoint or path-based gestures. Multipoint or path-based gestures can be used so long as the functionality can also be operated by another method, such as a tap, click, double tap, double click, long press, or click & hold." Why: "Some pointing methods lack the capability or accuracy to perform multipoint or path-based gestures." Smell: swipe-to-dismiss on a toast or card with no close button, a pinch-zoom map without plus and minus buttons, or a carousel that only advances on a horizontal flick. Source: https://www.w3.org/WAI/WCAG22/Understanding/pointer-gestures.html#intent
- **Pair every drag with a click or tap route, not just a keyboard one**: "achieving keyboard equivalence for a dragging operation does not automatically meet this success criterion, unless that equivalent keyboard operation also provides controls that can be clicked or tapped with a pointer." and "while a range slider is operated by dragging the slider thumb, an alternative pointer method to change the value is to click/tap anywhere on the slider track to move the thumb to that position." Why: "Not all users can accurately press and hold that contact while also repositioning the pointer." Smell: a kanban board with drag-and-drop plus arrow-key reordering but no "Move to" menu, or a custom slider that ignores `pointerdown` on its track. Source: https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html#intent
- **Act on the up-event, and give drags an abort or undo**: "The most accessible way to incorporate pointer cancellation is to make activation occur on the up-event." and "Designers may elect to confirm the move through something like a confirmation dialog or an undo button, giving the user the ability to Undo the process just completed." Why: "If they discover they have selected the wrong item, they can cancel the action by moving their pointer or finger away from the target before releasing." Smell: `onPointerDown={submit}` or `mousedown` and `touchstart` handlers that run the action, or a drop that commits at once with no undo and no revert when released outside a target. Source: https://www.w3.org/WAI/WCAG22/Understanding/pointer-cancellation.html#intent
- **Back every motion gesture with a control and a switch to turn motion off**: "functionality offered through motion must also be available by another mechanism." and "The user must have the ability to turn off motion actuation to prevent such accidental triggering of functions." Why: "some users may accidentally activate sensors due to tremors or other motor impairments." Smell: a `devicemotion` listener for shake-to-undo with no undo button and no setting, or tilt-to-scroll with no scrollbar. Source: https://www.w3.org/WAI/WCAG22/Understanding/motion-actuation.html#intent
- **Never lock the page to one input mechanism**: "Content must not limit the user's interaction to any particular input mechanism unless the restriction is essential, or is required to ensure the security of the content or to respect user settings." Why: "Users should be able to switch input mechanisms at any point should the user determine that certain tasks and interactions are more easily accomplished by using an alternative input mechanism." Smell: an `if ("ontouchstart" in window)` branch that removes mouse or keyboard handlers, or a "touch device" class that hides focus styles and hover-revealed controls for the whole session. Source: https://www.w3.org/WAI/WCAG22/Understanding/concurrent-input-mechanisms.html#intent
- **Treat `hover: none` as "the primary input cannot hover", not "no mouse exists"**: "The `hover` CSS media feature can be used to test whether the user's primary input mechanism can hover over elements." and `none` means "The primary input mechanism cannot hover at all or cannot conveniently hover (e.g., many mobile devices emulate hovering when the user performs an inconvenient long tap), or there is no primary pointing input mechanism." Why: a paired mouse or keyboard on a touch-first device is still in use, so the query should adjust presentation, not remove function. Smell: `@media (hover: none) { .tooltip, .secondary-actions { display: none; } }` with no replacement, or focus styles hidden inside `(hover: none)`. Baseline: Widely available (Interaction media queries, widely since 2021-06-11). Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/hover#syntax

## Motion and flashing

- **Never flash more than three times a second over a large area**: ""Flashing" refers to content that can trigger a seizure (if it is more than 3 per second and large and bright enough). This cannot be allowed even for a second or it could cause a seizure." The threshold area: "the combined area of flashing becomes 341 x 256 CSS pixels, or a flashing area of 87,296 CSS pixels." Why: "Individuals who have photosensitive seizure disorders can have a seizure triggered by content that flashes at certain frequencies for more than a few flashes." Smell: `@keyframes blink { 50% { opacity: 0; } }` with an `animation-duration` under 333ms on a banner, a full-viewport background that toggles on each error, or a looping GIF with strobe frames. Source: https://www.w3.org/WAI/WCAG22/Understanding/three-flashes-or-below-threshold.html#intent
- **Keep saturated red out of anything that flashes**: "A red flash is defined as any pair of opposing transitions involving a saturated red." Why: "Irrespective of luminance, a transition to or from a saturated red is also considered a risk." Smell: an alert that pulses between `#ff0000` and white, or a recording indicator blinking in `hsl(0 100% 50%)`. Source: https://developer.mozilla.org/en-US/docs/Web/Accessibility/Guides/Seizure_disorders#flashing__flashing_red
- **Lower contrast in moving content rather than raising it**: ""Safer" animation means images with less contrast, not more." Why: "In general, for accessibility purposes, the more contrast, the better. That changes with animation." Smell: an animated hero that alternates pure black and pure white frames, or a loading spinner of high-contrast stripes rotating fast enough to flicker. Source: https://developer.mozilla.org/en-US/docs/Web/Accessibility/Guides/Colors_and_Luminance#contrast_and_font_size
- **Give moving content that runs past 5 seconds a real pause control, and count indirect triggers as automatic**: "Five seconds was chosen because it is long enough to get a user's attention, but not so long that a user cannot wait out the distraction if necessary to use the page." "Having an animation stop only so long as a user has focus on it (where it restarts as soon as the user moves the focus away) would not be considered a "mechanism for the user to pause" because it makes the page unusable in the process and would not meet this SC." and content counts as starting automatically "when it starts as a result of an indirect interaction (such as focusing/hovering over an element, or scrolling an element into view)." Why: "Some people with cognitive disabilities and attention deficits are distracted by continuous movement." Smell: `animation: marquee 20s linear infinite` on a ticker with no button, a carousel whose only pause is `:hover`, or an `IntersectionObserver` that starts a looping animation when a section scrolls into view. Source: https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html#intent
- **Give parallax and scroll-linked motion a reduced-motion path**: "Another animation that is often non-essential is parallax scrolling. Parallax scrolling occurs when backgrounds move at a different rate to foregrounds." and "Take advantage of the reduce motion feature in the user agent or operating system." Why: "Vestibular (inner ear) disorder reactions include dizziness, nausea and headaches." Smell: scroll-driven `transform: translateY()` layers, `animation-timeline: scroll()`, or a page-flip transition with no `@media (prefers-reduced-motion: reduce)` override and no site-wide setting. Source: https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html#intent
- **Reduce motion, do not nuke every animation**: "The value of `prefers-reduced-motion` is `reduce`, not "none". This preference does not mean all animations must be removed, which could be achieved with `* {animation: none !important;}`. Rather, users expect motion animation, including those triggered by user interaction, to be disabled unless the animation is essential to the functionality or the information being conveyed". Why: "certain kinds of motion can be a trigger for Vestibular disorders, epilepsy, and migraine and Scotopic sensitivity." Smell: `@media (prefers-reduced-motion: reduce) { * { animation: none !important; transition: none !important; } }` that also kills opacity fades and progress indicators. Baseline: Widely available since 2022-07-15. Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Media_queries/Using_for_accessibility#reduced_motion
- **Swap scaling and panning for a fade under reduced motion**: "Animations such as scaling or panning large objects can be vestibular motion triggers." The example tones the effect down "to the `dissolve` animation, which is a more muted animation that is not a vestibular motion trigger." Why: the preference asks for movement to go, not for feedback to go. Smell: `transform: scale()` or `translateX(100vw)` entrance animations with no reduced-motion alternative such as an opacity change. Baseline: Widely available since 2022-07-15. Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion#examples
- **Shorten durations to near zero instead of `animation: none` when code waits on the animation**: "Setting `animation-duration` and `transition-duration` properties to a short duration rather than setting them to `animation: none` and `transition: none`, enables a safeguard to prevent issues in any case there is a dependency on the animation to run." Why: an `animationend` or `transitionend` listener never fires if the animation is removed, so the interface can stall. Smell: `animation: none` under reduced motion on a dialog whose close handler runs on `transitionend`. Source: https://developer.mozilla.org/en-US/docs/Web/Accessibility/Guides/Seizure_disorders#css_for_animation
- **Do not animate text**: "Moving text can induce seizures for the same reasons that moving images do, so avoid animating your text." Why: "many screen readers cannot read moving text and it's bad user experience even for those with no vision or vestibular issues." Smell: `<marquee>` or `<blink>`, or a CSS marquee of headline text with `animation: scroll-left 10s linear infinite`. Lint: `jsx-a11y/no-distracting-elements`. Source: https://developer.mozilla.org/en-US/docs/Web/Accessibility/Guides/Seizure_disorders#control_speed

## Time limits

- **Let users turn off, lengthen or extend every time limit**: "Let users turn off, adjust, or extend time limits." in that order of preference: "Disabling time limits is better than customizing the length of time limits, which is better than requesting more time before a time limit occurs." The warning itself needs time: "For "hit any key," 20 seconds would meet this." and the extension should be generous: "Ten times the default was chosen based on clinical experience and other guidelines." Why: "People with disabilities such as blindness, low vision, dexterity impairments, and cognitive limitations may require more time to read content or to perform functions such as filling out on-line forms." Smell: `setTimeout(signOut, 15 * 60 * 1000)` with no warning, or a "session expiring" dialog that itself disappears after 5 seconds. Source: https://www.w3.org/WAI/WCAG22/Understanding/timing-adjustable.html#intent
- **Treat auto-refresh and moving content as a time limit**: "Any process that happens without user initiation after a set time or on a periodic basis is a time limit. This includes partial or full updates of content (for example, page refresh), changes to content, or the expiration of a window of opportunity for a user to react to a request for input." and "animated, moving or scrolling content introduces a time limit on a user's ability to read content." Why: readers need control over the pace at which content changes under them. Smell: `setInterval(refreshFeed, 10000)` that replaces list items while they are being read, or `<meta http-equiv="refresh" content="30">`. Source: https://www.w3.org/WAI/WCAG22/Understanding/timing-adjustable.html#intent
- **Keep transient messages redundant or persistent**: "If the user has no other means of discovering the same information (or performing the same function), then each message would need to meet this success criterion in order to provide users with sufficient time to access the information." Why: "Content that operates on a timer does not need to be time adjustable if there is an alternative that does not rely on a timer." Smell: an error or success toast that auto-hides after 5 seconds and is the only place the message appears. Source: https://www.w3.org/WAI/WCAG22/Understanding/timing-adjustable.html#intent
- **Preserve data for 20 hours or warn about inactivity at the start**: "The best way to conform to this success criterion is to keep the user data for at least 20 hours." and "when it is not practical to save the user data the author must warn the user about the duration of inactivity which will result in a timeout. Timeouts should be displayed to the user once at the beginning of the related task or process and not at each step." Why: "Users should be able to leave a process without losing their current place within the process, and without losing information that has already been entered." Smell: a multi-step form whose state lives only in memory behind a 30-minute session, with no notice on step one. Source: https://www.w3.org/WAI/WCAG22/Understanding/timeouts.html#intent

## User preference media features

- **Offer stronger borders and text under `prefers-contrast: more`**: `more` "Indicates that user has notified the system that they prefer an interface that has a higher level of contrast." and the example: "When the `prefers-contrast: more` media query matches, the applied outline is given a higher contrast `solid` style instead." Why: a reader who asked the operating system for more contrast is telling the page that its default ratios are not enough for them. Smell: a token theme with `1px dashed #ddd` dividers, grey placeholders and translucent borders, and no `@media (prefers-contrast: more)` variant. Baseline: Widely available since 2024-11-30. Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-contrast#syntax
- **Tweak, do not redesign, for `forced-colors: active`**: "web authors should not be using the `forced-colors` media feature to create a separate design for users with this feature enabled. Instead, its intended usage is to make small tweaks to improve usability or legibility when the default application of forced colors does not work well for a given portion of a page." Why: "The high contrast provided by forced colors mode's reduced palette and text backplates is often essential for some users to be able to read or use a given website, so adjustments that affect content should be chosen carefully and targeted to content that is otherwise not legible." Smell: an `@media (forced-colors: active)` block that re-applies brand colours, or that hides components outright. Baseline: Widely available since 2025-03-12. Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/forced-colors#accessibility_concerns
- **Draw boundaries with borders and system colours, not shadows or gradients**: "`box-shadow` is forced to 'none'" and "`background-image` is forced to 'none' for values that are not url-based", while "When a system color is specified, it will be used instead of the value that would otherwise have been forced." Why: "In forced colors mode, the values of the following properties are treated as if they have no author-level values specified." so anything drawn only with shadows, gradients or hex colours vanishes or clashes with the user's palette. Smell: a focus ring or button edge drawn only with `box-shadow: 0 0 0 2px`, a checkbox tick made of `linear-gradient`, a toggle with `border: 0` (use `border: 2px solid transparent` so it reappears), or `@media (forced-colors: active) { .btn { border-color: #0057b8; } }` instead of `ButtonText`. Baseline: Widely available since 2025-03-12. Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/forced-colors#properties_affected_by_forced-color_mode
- **Reserve `forced-color-adjust: none` for cases that help the user**: "This property should only be used to makes changes that will support a user's color and contrast requirements." and "It should not be used to prevent user choices being respected". Why: the reader chose the palette so they could read, and a colour swatch or chart where the exact colour is the information is the only kind of exception that serves them. Smell: `* { forced-color-adjust: none; }`, or `forced-color-adjust: none` on a brand header rather than on a colour picker swatch. Baseline: not listed separately (Forced colors is Widely available since 2025-03-12). Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/forced-color-adjust#usage_notes
- **Firm up glass effects under `prefers-reduced-transparency`**: "If the setting to reduce transparency is enabled in the accessibility preferences on your device, the translucent box becomes more opaque." Why: "Switching on such a setting can help improve contrast and readability for some users." Smell: `backdrop-filter: blur(20px); background: rgb(255 255 255 / 0.3);` on a sticky header over scrolling content, with no `@media (prefers-reduced-transparency)` branch that raises the opacity. Baseline: Limited availability. Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-transparency#examples
