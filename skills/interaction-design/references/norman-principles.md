# Norman: actions and understanding

Original guidance, paraphrased for interface review. Sources: Don Norman, [Signifiers, not affordances](https://jnd.org/signifiers-not-affordances/) and [Design as Communication](https://jnd.org/design-as-communication/). The broader foundation is *The Design of Everyday Things*, revised edition (2013); this file is a practical synthesis, not an exhaustive extraction.

- **Discoverability:** inspect whether someone can identify available actions before trying them. Example: expose the row action that is otherwise visible only on hover.
- **Signifiers and affordances:** separate what an interface allows from the cues that communicate it. An icon can signal an action without explaining its scope; a label may resolve that ambiguity.
- **Mapping:** compare a control's position and effect. Example: place each quantity control with its corresponding item. Spatial conventions may vary with language and context.
- **Feedback:** show the result of an action at a useful time and location. Example: indicate whether saving is pending, complete or failed while preserving the draft.
- **Constraints:** prevent invalid actions while explaining what enables them. A disabled control with no explanation can leave the user stuck.
- **Conceptual models:** check whether terminology and behaviour let users predict outcomes. Example: distinguish archiving from deletion through names, placement and recovery.

These are prompts for examining a task, not universal prescriptions for particular widgets. A screenshot cannot demonstrate whether feedback arrives in time or whether a conceptual model matches a user's understanding.
