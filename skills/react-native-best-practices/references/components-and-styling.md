# React Native code-review rules: components and styling

Extracted 2026-11-12 from the React Native 0.88 documentation (facebook/react-native-website, CC BY 4.0) and the Expo SDK 58 documentation (expo/expo, MIT). One rule per bullet, one source link each. Quotations are short excerpts; the rest is original.

## View

- **Extend small touch targets with `hitSlop`**: "Typical interface guidelines recommend touch targets that are at least 30 - 40 points/density-independent pixels." - when an icon or link is visually small, add `hitSlop` or padding so the pressable area reaches that size. Why: a 16 point icon with no slop is routinely missed. Smell: a pressable icon of `width: 16, height: 16` with no `hitSlop` and no padding. Source: https://reactnative.dev/docs/view#hitslop
- **Do not rely on `hitSlop` to reach outside the parent**: "The touch area never extends past the parent view bounds, and the Z-index of sibling views always takes precedence if a touch hits two overlapping views." - give the parent room, or move the handler up, when the target sits at the parent's edge. Why: slop that crosses the parent boundary is silently clipped. Smell: `hitSlop={20}` on a close button pinned to the corner of a tight container. Source: https://reactnative.dev/docs/view#hitslop
- **Set `collapsable={false}` on a layout-only view that native code must find**: "Views that are only used to layout their children or otherwise don't draw anything may be automatically removed from the native hierarchy as an optimization." - a wrapper with no visual style can vanish, so opt out when it is measured or targeted. Why: "Set this property to `false` to disable this optimization and ensure that this `View` exists in the native view hierarchy." Smell: a ref to a bare wrapper `<View>` whose measurement comes back empty on one platform. Source: https://reactnative.dev/docs/view#collapsable
- **Use `pointerEvents='box-none'` for overlay containers**: "The View is never the target of touch events but its subviews can be." - a full-screen wrapper that only positions floating children should not swallow touches meant for the content beneath. Why: an absolutely filled wrapper with the default `'auto'` blocks everything under it. Smell: an absolute-fill `<View>` holding one floating button, after which the list beneath stops responding. Source: https://reactnative.dev/docs/view#pointerevents
- **Switch `renderToHardwareTextureAndroid` off after the animation** (Android only): "this prop should be set back to false at the end of the interaction/animation" - toggle it on for the duration of an opacity, rotation, translation or scale animation only. Why: "The downside is that this can use up limited video memory". Smell: `renderToHardwareTextureAndroid` hard-coded to `true` on a long-lived view. Source: https://reactnative.dev/docs/view#rendertohardwaretextureandroid-android
- **Give `removeClippedSubviews` the overflow it needs**: "The subviews must also have `overflow: hidden`, as should the containing view (or one of its superviews)." - the prop only works on a view with many children extending outside its bounds, and only with that overflow setting. Why: without it the property has no effect. Smell: `removeClippedSubviews` on a plain `View` with default overflow. Source: https://reactnative.dev/docs/view#removeclippedsubviews

## Text

- **Wrap every string in `<Text>`**: "You cannot have a text node directly under a `<View>`." - any literal, number or interpolated string must sit inside a `Text` element. Why: "you must wrap all the text nodes inside of a `<Text>` component". Smell: `<View>{count}</View>`, or `{label && <Icon />}` where `label` can be an empty string or `0`. Source: https://reactnative.dev/docs/text#limited-style-inheritance
- **Set shared typography through one text component**: "The recommended way to use consistent fonts and sizes across your application is to create a component `MyAppText` that includes them and use this component across your app." - build the app's text component once and compose variants from it. Why: "You also lose the ability to set up a default font for an entire subtree." Smell: `fontFamily` and `fontSize` repeated in dozens of style objects, or a font set on a parent `View` in the hope it cascades. Source: https://reactnative.dev/docs/text#limited-style-inheritance
- **Pass one font name to `fontFamily`**: "`fontFamily` only accepts a single font name, which is different from `font-family` in CSS" - handle fallbacks per platform in code, not in a comma-separated stack. Why: a CSS-style stack is not a valid font name here. Smell: `fontFamily: 'Inter, Helvetica, sans-serif'`. Source: https://reactnative.dev/docs/text#limited-style-inheritance
- **Do not lay out children of `<Text>` with flexbox**: "everything inside is no longer using the Flexbox layout but using text layout" - place rows, gaps and alignment on a `View` and keep only inline runs inside `Text`. Why: "elements inside of a `<Text>` are no longer rectangles, but wrap when they see the end of the line". Smell: `flexDirection`, `justifyContent` or `gap` on a `Text` that has nested elements. Source: https://reactnative.dev/docs/text#containers
- **Pair `ellipsizeMode` with `numberOfLines`**: "`numberOfLines` must be set in conjunction with this prop." - truncation mode does nothing without a line limit. Why: the text simply wraps and the intended ellipsis never shows. Smell: `ellipsizeMode='middle'` with no `numberOfLines`. Source: https://reactnative.dev/docs/text#ellipsizemode
- **Use only `tail` truncation for multi-line text on Android**: "On Android, when `numberOfLines` is set to a value higher than `1`, only `tail` value will work correctly." - choose `tail`, or restrict `head` and `middle` to single-line text. Why: other modes render incorrectly on Android. Smell: `numberOfLines={2}` with `ellipsizeMode='head'`. Source: https://reactnative.dev/docs/text#ellipsizemode
- **Cap font scaling with `maxFontSizeMultiplier` instead of disabling it**: "Specifies the largest possible scale a font can reach when `allowFontScaling` is enabled." - when large text breaks a fixed layout, set a ceiling of 2 or more rather than `allowFontScaling={false}`; a lower ceiling stops text reaching double size. Why: `allowFontScaling` exists so that fonts "scale to respect Text Size accessibility settings". Smell: `allowFontScaling={false}` added in the same commit as a fixed-height container. Source: https://reactnative.dev/docs/text#maxfontsizemultiplier
- **Remove Android font padding when centring text vertically** (Android only): "With some fonts, this padding can make text look slightly misaligned when centered vertically." - set `includeFontPadding: false`, ideally with `textAlignVertical: 'center'`. Why: the extra padding shifts glyphs off centre in badges and buttons. Smell: a platform-specific `marginTop: -2` hack on a label inside a pill. Source: https://reactnative.dev/docs/text-style-props#includefontpadding-android

## Pressable, Button and Touchables

- **Choose `Pressable` over the Touchable components in new code**: "If you're looking for a more extensive and future-proof way to handle touch-based input, check out the Pressable API." - every Touchable page opens with this pointer, so new press handling belongs in `Pressable`. Why: the docs describe `Pressable` as the forward-looking API and the Touchables as the older set. Smell: a newly added import of `TouchableOpacity` or `TouchableHighlight`. Source: https://reactnative.dev/docs/touchableopacity
- **Build custom buttons from `Pressable`, not from a restyled `Button`**: "If this button doesn't look right for your app, you can build your own button using Pressable." - `Button` is for the stock platform look only. Why: it "Supports a minimal level of customization." Smell: a `Button` wrapped in views with negative margins or overlays to fake a design. Source: https://reactnative.dev/docs/button
- **Remember that `Button` `color` means different things per platform**: "Color of the text (iOS), or background color of the button (Android)." - check both platforms, or use a `Pressable` when the colour must mean one thing. Why: one value yields a tinted label on iOS and a filled rectangle on Android. Smell: `color='#fff'` on a `Button`, which gives white text on iOS and a white block on Android. Source: https://reactnative.dev/docs/button#color
- **Avoid `TouchableWithoutFeedback`**: "Do not use unless you have a very good reason. All elements that respond to press should have a visual feedback when touched." - use `Pressable` with a pressed style. Why: a control with no pressed state looks unresponsive. Smell: `TouchableWithoutFeedback` around a card or list row. Source: https://reactnative.dev/docs/touchablewithoutfeedback
- **Forward props through the single child of `TouchableWithoutFeedback`**: "It is therefore required that any intermediary components pass through those props to the underlying React Native component." - it clones one child and injects responder props, so a custom child must spread them onto a native component. Why: "`TouchableWithoutFeedback` supports only one child." Smell: a custom component as the child that ignores its rest props, so `onPress` never fires. Source: https://reactnative.dev/docs/touchablewithoutfeedback
- **Set an opaque background on the child of `TouchableHighlight`**: "if the backgroundColor of the wrapped view isn't explicitly set to an opaque color" - the docs name this as a cause of visual artefacts, because the underlay shows through the child. Why: the underlay comes from "wrapping the child in a new View, which can affect layout". Smell: a `TouchableHighlight` child with no `backgroundColor`, flashing a dark rectangle on press. Source: https://reactnative.dev/docs/touchablehighlight
- **Account for the extra view `TouchableOpacity` inserts**: "Opacity is controlled by wrapping the children in an `Animated.View`, which is added to the view hierarchy. Be aware that this can affect layout." - put flex and sizing styles on the touchable itself. Why: the wrapper becomes the flex child, so styles on the inner view no longer size the row. Smell: `flex: 1` on the child of a `TouchableOpacity` that collapses to content size. Source: https://reactnative.dev/docs/touchableopacity
- **Guard `TouchableNativeFeedback` by platform** (Android only): "A wrapper for making views respond properly to touches (Android only)." - render it only on Android, with a single `View` child. Why: "it only supports having a single View instance as a child node". Smell: `TouchableNativeFeedback` rendered with no `Platform` check in shared code. Source: https://reactnative.dev/docs/touchablenativefeedback
- **Show pressed state through the `style` function**: "Either view styles or a function that receives a boolean reflecting whether the component is currently pressed and returns view styles." - derive feedback from `pressed` instead of tracking it in component state. Why: `onPressIn` and `onPressOut` state duplicates what `Pressable` already knows and adds renders. Smell: `useState` named `isPressed` toggled by `onPressIn` and `onPressOut`. Source: https://reactnative.dev/docs/pressable#style
- **Tune long presses with `delayLongPress`, not timers**: "Called if the time after `onPressIn` lasts longer than 500 milliseconds." - set `delayLongPress` to change the threshold. Why: "This time period can be customized with" that prop, so a hand-written timer duplicates it and leaks on unmount. Smell: `setTimeout` started in `onPressIn` and cleared in `onPressOut`. Source: https://reactnative.dev/docs/pressable#onlongpress

## TextInput

- **Block edits with `editable` or `maxLength`, not by re-setting `value`**: "either set `editable={false}`, or set/update `maxLength` to prevent unwanted edits without flicker" - a controlled input that rejects characters by keeping the old value flashes the rejected text. Why: "the native value will be forced to match this value prop if provided". Smell: an `onChangeText` handler that returns early without updating state to refuse input. Source: https://reactnative.dev/docs/textinput#value
- **Limit length with `maxLength`**: "Use this instead of implementing the logic in JS to avoid flicker." - let the native field enforce the limit. Why: slicing in `onChangeText` shows the extra character for a frame. Smell: `setText(t.slice(0, 20))` with no `maxLength`. Source: https://reactnative.dev/docs/textinput#maxlength
- **Replace `blurOnSubmit` with `submitBehavior`** (deprecated): "`submitBehavior` now takes the place of `blurOnSubmit` and will override any behavior defined by `blurOnSubmit`" - use `'submit'`, `'blurAndSubmit'` or `'newline'`. Why: when both are present the deprecated prop is ignored. Smell: `blurOnSubmit={false}` on a chat or multi-field form input. Source: https://reactnative.dev/docs/textinput#submitbehavior
- **Use `autoComplete` alone for autofill hints**: "Avoid using both `textContentType` and `autoComplete`." - `autoComplete` covers both platforms, with `Platform.select` for the differences. Why: "For backwards compatibility, `textContentType` takes precedence when both properties are set." Smell: `textContentType='password'` beside `autoComplete='new-password'` on one field. Source: https://reactnative.dev/docs/textinput#textcontenttype-ios
- **Align multiline text to the top on both platforms**: "this aligns the text to the top on iOS, and centers it on Android" - add `textAlignVertical: 'top'` to multiline inputs. Why: the same component otherwise starts typing in the middle of the box on Android. Smell: `multiline` with a fixed height and no `textAlignVertical`. Source: https://reactnative.dev/docs/textinput#multiline
- **Do not combine `secureTextEntry` with `multiline`**: "Does not work with `multiline={true}`." - password fields must be single-line. Why: the text is not obscured, which exposes the secret. Smell: `secureTextEntry` and `multiline` on the same input. Source: https://reactnative.dev/docs/textinput#securetextentry
- **Do not combine `secureTextEntry` with email or phone keyboards on Android**: "Doesn't support Android's `secureTextEntry` when" - the known issue covers `keyboardType` values `email-address` and `phone-pad`. Why: the field may show its contents in clear text on Android. Smell: a PIN field with `secureTextEntry` and `keyboardType='phone-pad'`. Source: https://reactnative.dev/docs/textinput#known-issues
- **Read the final value from `onEndEditing`, not from `onBlur`**: "the resulting value you get can be `undefined` which can cause unintended errors" - `nativeEvent.text` is not reliable in the blur event. Why: the docs point to `onEndEditing`, "which is fired upon completion of editing". Smell: `onBlur={e => validate(e.nativeEvent.text)}`. Source: https://reactnative.dev/docs/textinput#onblur
- **Set only one of `inputMode` and `keyboardType`**: "has precedence over `keyboardType`" - when `inputMode` is present the other prop is ignored. Why: two keyboard settings on one input hide which one applies. Smell: `inputMode='numeric'` with `keyboardType='email-address'`. Source: https://reactnative.dev/docs/textinput#inputmode
- **Handle the Android underline when setting an explicit height**: "Solutions to avoid this are to either not set height explicitly" - or hide the border by setting `underlineColorAndroid` to transparent. Why: the border's padding is "set by the background image provided by the system, and it cannot be changed". Smell: a fixed-height `TextInput` with a misplaced line under the text on Android. Source: https://reactnative.dev/docs/textinput
- **Check absolutely positioned views against Android keyboard resizing**: "This may cause issues with components that have position: 'absolute' while the keyboard is active." - text selection can switch the activity to `adjustResize`; declare `windowSoftInputMode` in the manifest so the behaviour is fixed. Why: a pinned footer jumps above the keyboard only after the user selects text. Smell: an absolute bottom bar on a screen with inputs and no `windowSoftInputMode` set. Source: https://reactnative.dev/docs/textinput
- **Do not style per-side borders or per-corner radii on `TextInput`**: "Note that not all Text styles are supported" - the listed gaps include `borderLeftWidth` to `borderBottomWidth` and the four corner radius properties, so draw those on a wrapping `View`. Why: the unsupported properties are dropped without a warning. Smell: `borderBottomWidth: 1` directly on a `TextInput` style. Source: https://reactnative.dev/docs/textinput#style

## Image

- **Give network and data images explicit dimensions**: "For network and data images, you will need to manually specify the dimensions of your image!" - set `width` and `height`, or one dimension with `aspectRatio`. Why: without a size the image occupies no space and nothing is drawn. Smell: `<Image source={{uri}} />` with no size in its style. Source: https://reactnative.dev/docs/image
- **Keep `require` paths for images static**: "In order for this to work, the image name in `require` has to be known statically." - select between whole `require` calls instead of building the path. Why: the bundler resolves images at build time and cannot follow a computed string. Smell: `require('./icons/' + name + '.png')`. Source: https://reactnative.dev/docs/images#static-image-resources
- **Load remote images over https**: "It's highly recommended that you use https as well in order to satisfy" - the sentence continues with the App Transport Security requirements on iOS. Why: plain http image requests are blocked on iOS by default. Smell: an image `uri` starting with `http://`. Source: https://reactnative.dev/docs/images#network-images
- **Add the Fresco modules before using GIF or WebP on Android**: "When building your own native code, GIF and WebP are not supported by default on Android." - add the optional dependencies in `android/app/build.gradle`. Why: the image renders static or not at all on Android while working on iOS. Smell: a `.gif` or `.webp` source added with no change to the Android Gradle file. Source: https://reactnative.dev/docs/image#gif-and-webp-support-on-android
- **Do not load remote WebP on iOS**: "the `webp` format is supported on iOS only when bundled with the JavaScript code" - bundle the asset or serve another format to iOS. Why: a remote `.webp` URL fails to display on iOS. Smell: a CDN `uri` ending in `.webp` with no platform branch. Source: https://reactnative.dev/docs/image#source
- **Avoid `resizeMethod='none'`** (Android only): "This should only be used in rare circumstances because it is considered unsafe as Android will throw a runtime exception when trying to render images that consume too much memory." - leave the default `auto` unless a measured need exists. Why: a large user-supplied photo crashes the app. Smell: `resizeMethod='none'` on images whose source size is not controlled. Source: https://reactnative.dev/docs/image#resizemethod-android
- **Round individual image corners with a clipping wrapper on iOS**: "the following corner specific, border radius style properties might be ignored by iOS's image component" - put `borderTopLeftRadius` and its siblings on a parent `View` with `overflow: 'hidden'`. Why: the corner styles may have no effect on the image itself. Smell: `borderTopLeftRadius` and `borderTopRightRadius` set directly on an `Image`. Source: https://reactnative.dev/docs/images#ios-border-radius-styles
- **Preload with `Image.prefetch`, not `Image.getSize`**: "Prefetches a remote image for later use by downloading it to the disk cache." - use `getSize` only when the dimensions are needed. Why: for `getSize` the docs say preloading is possible in principle, but "it is not optimized for that purpose". Smell: `Image.getSize(url, () => {})` with an empty callback used to warm the cache. Source: https://reactnative.dev/docs/image#prefetch
- **Reset intrinsic size when a bundled image must flex**: "you may need to manually set `{width: undefined, height: undefined}` on the style attribute" - required images carry their own width and height, which override flex sizing. Why: the image stays at its file dimensions and overflows the container. Smell: a `require`d banner with `flex: 1` that renders at its pixel size. Source: https://reactnative.dev/docs/images#static-image-resources

## ScrollView

- **Give every `ScrollView` a bounded height**: "ScrollViews must have a bounded height in order to work" - make sure each ancestor passes height down, usually with `flex: 1`. Why: "Forgetting to transfer `{flex: 1}` down the view stack can lead to errors here". Smell: a `ScrollView` inside a wrapper `View` with no `flex` and no height, where content is cut off and will not scroll. Source: https://reactnative.dev/docs/scrollview
- **Use `FlatList` for long lists**: "If you have a long list of items which cannot fit on the screen, you should use a `FlatList` instead." - keep `ScrollView` for a small, bounded amount of content. Why: "`ScrollView` renders all its react child components at once, but this has a performance downside." Smell: `items.map(...)` over server data inside a `ScrollView`. Source: https://reactnative.dev/docs/using-a-scrollview
- **Put inner layout on `contentContainerStyle`**: "These styles will be applied to the scroll view content container which wraps all of the child views." - padding, alignment and `flexGrow` for the children belong there, while `style` sizes the scroll view frame. Why: `alignItems` or `justifyContent` on `style` targets the wrong view. Smell: `<ScrollView style={{padding: 16, alignItems: 'center'}}>`. Source: https://reactnative.dev/docs/scrollview#contentcontainerstyle
- **Set `keyboardShouldPersistTaps` on scroll views that hold inputs and buttons**: "tapping outside of the focused text input when the keyboard is up dismisses the keyboard. When this happens, children won't receive the tap." - that describes the default `'never'`; use `'handled'` so a submit button works on the first tap. Why: the first tap only closes the keyboard and the user must tap again. Smell: a form in a `ScrollView` with no `keyboardShouldPersistTaps`. Source: https://reactnative.dev/docs/scrollview#keyboardshouldpersisttaps
- **Do not rely on interactive keyboard dismissal on Android**: "On Android this is not supported and it will have the same behavior as `'none'`." - choose `'on-drag'` for Android or add another way to dismiss. Why: `keyboardDismissMode='interactive'` leaves Android users unable to close the keyboard by dragging. Smell: `keyboardDismissMode='interactive'` with no platform branch. Source: https://reactnative.dev/docs/scrollview#keyboarddismissmode
- **Treat `removeClippedSubviews` on a scroll view as a risk**: "Using this property may lead to bugs (missing content) in some circumstances - use at your own risk." - enable it deliberately and test, remembering that "On Android the default value is `true`." Why: rows can go blank. Smell: `removeClippedSubviews` added as a blanket performance fix with no linked measurement. Source: https://reactnative.dev/docs/scrollview#removeclippedsubviews
- **Use `refreshControl` only on vertical scroll views**: "Only works for vertical ScrollViews (`horizontal` prop must be `false`)." - a horizontal carousel needs a different refresh affordance. Why: the control never appears. Smell: `refreshControl` together with `horizontal`. Source: https://reactnative.dev/docs/scrollview#refreshcontrol
- **Do not reorder content under `maintainVisibleContentPosition`**: "don't re-order the content of any ScrollViews or Lists that use this feature" - append or prepend only. Why: reordering "will probably cause jumpiness and jank". Smell: a sorted or drag-reorderable list with `maintainVisibleContentPosition` set. Source: https://reactnative.dev/docs/scrollview#maintainvisiblecontentposition
- **Call `scrollTo` with an options object** (positional form deprecated): "This is deprecated due to ambiguity (y before x), and SHOULD NOT BE USED." - write `scrollTo({x: 0, y: 0, animated: true})`. Why: the positional form takes `y` before `x`, so swapped arguments scroll the wrong axis. Smell: `ref.current.scrollTo(0, 200, true)`. Source: https://reactnative.dev/docs/scrollview#scrollto

## StyleSheet and the style prop

- **Create styles with `StyleSheet.create`**: "The main practical benefit of creating styles inside `StyleSheet.create()` is static type checking against native style properties." - define styles once at module scope. Why: a misspelt or web-only property is caught at compile time instead of being ignored at runtime. Smell: a plain object literal of styles typed as `any`, or `style={{dispaly: 'none'}}` passing review. Source: https://reactnative.dev/docs/stylesheet#create
- **Order style arrays from base to override**: "the last style in the array has precedence, so you can use this to inherit styles" - put the base first and the conditional or incoming style last. Why: the wrong order silently discards the override. Smell: `style={[props.style, styles.base]}` in a reusable component. Source: https://reactnative.dev/docs/style
- **Accept and forward a `style` prop in reusable components**: "make your component accept a `style` prop which in turn is used to style subcomponents" - merge it after the component's own styles. Why: this is the documented way to make styles "cascade", since there is no inheritance between views. Smell: a shared component that offers `marginTop`, `marginBottom` and `width` as separate props. Source: https://reactnative.dev/docs/style
- **Use `StyleSheet.absoluteFill` for full overlays**: "`absoluteFill` can be used for convenience and to reduce duplication of these repeated styles" - replace hand-written absolute position with four zero offsets. Why: the repeated block is easy to get subtly wrong. Smell: `position: 'absolute', top: 0, left: 0, right: 0, bottom: 0` copied into several files. Source: https://reactnative.dev/docs/stylesheet#absolutefill
- **Do not use negative margins for overlap on Android**: "on Android negative margin is not supported" - use absolute positioning or transforms. Why: the layout differs between platforms, and "the touch area never extends past the parent view bounds". Smell: `marginTop: -20` to pull an avatar over a header. Source: https://reactnative.dev/docs/style#known-issues

## Sizing and units

- **Write dimensions as unitless numbers**: "All dimensions in React Native are unitless, and represent density-independent pixels." - pass numbers, not CSS length strings. Why: a string such as `'16px'` is not a valid dimension. Smell: `width: '100px'` or `fontSize: '1rem'`. Source: https://reactnative.dev/docs/height-and-width#fixed-dimensions
- **Use only points or percentages for layout values**: "in React Native you must use points or percentages. Ems and other units are not supported." - convert `em`, `rem` and `vh` values from web designs. Why: other units are rejected. Smell: `height: '50vh'` or `marginTop: '2em'`. Source: https://reactnative.dev/docs/layout-props#height
- **Give the parent a size before using `flex` on children**: "If a parent does not have either a fixed `width` and `height` or `flex`, the parent will have dimensions of `0` and the `flex` children will not be visible." - trace `flex: 1` or explicit dimensions up to the root. Why: the child renders nothing and no error is raised. Smell: `flex: 1` on a child whose parent `View` has no style. Source: https://reactnative.dev/docs/height-and-width#flex-dimensions
- **Read window size with `useWindowDimensions` in components**: "is the preferred API for React components. Unlike `Dimensions`, it updates as the window's dimensions update." - call the hook where the size is used. Why: rotation, split screen and foldables change the window while the app runs. Smell: `Dimensions.get('window')` inside a function component. Source: https://reactnative.dev/docs/dimensions
- **Do not store `Dimensions.get` results in a `StyleSheet`**: "using inline styles rather than setting a value in a `StyleSheet`" - the docs give this as the way to avoid caching a size that can change. Why: dimensions "may change (e.g due to device rotation, foldable devices etc)". Smell: `const {width} = Dimensions.get('window')` at module scope feeding `StyleSheet.create`. Source: https://reactnative.dev/docs/dimensions
- **Do not treat the Android window height as the full screen**: "For Android the `window` dimension will be reduced by the size of status bar (if not translucent) and bottom navigation bar." - size full-screen content with flex, not with the window height. Why: the same calculation gives different results on the two platforms. Smell: `height: Dimensions.get('window').height` on a root container. Source: https://reactnative.dev/docs/dimensions#get

## Flexbox and layout

- **Set `flexDirection: 'row'` explicitly for horizontal layouts**: "`flexDirection` defaulting to `column` instead of `row`" - web habits do not carry over. Why: children stack vertically by default. Smell: an icon and a label expected side by side in a `View` with no `flexDirection`. Source: https://reactnative.dev/docs/flexbox
- **Add `flexShrink: 1` where content must shrink**: "`flexShrink` defaulting to `0` instead of `1`" - text or views in a row will not shrink to fit unless told to. Why: long text pushes its siblings off screen instead of wrapping. Smell: a row with an icon and a long `Text` with no `flexShrink` or `flex: 1`, overflowing the screen. Source: https://reactnative.dev/docs/flexbox
- **Pass a single number to `flex`**: "`flex` is a number rather than a string" - the CSS shorthand `'1 1 auto'` is not accepted; set `flexGrow`, `flexShrink` and `flexBasis` separately when needed. Why: a positive value "equates to `flexGrow: <positive number>, flexShrink: 1, flexBasis: 0`". Smell: `flex: '1 0 auto'`. Source: https://reactnative.dev/docs/layout-props#flex
- **Remove the fixed cross-axis size when expecting `stretch`**: "For `stretch` to have an effect, children must not have a fixed dimension along the secondary axis." - delete the `width` in a column or the `height` in a row. Why: the fixed dimension wins and the child does not fill. Smell: `alignItems: 'stretch'` on a column whose children each set `width: 50`. Source: https://reactnative.dev/docs/flexbox#align-items
- **Set `alignItems` when using `flexWrap`**: "Note it does not work anymore with `alignItems: stretch` (the default), so you may want to use `alignItems: flex-start` for example" - a wrapping container needs an explicit non-stretch alignment. Why: the items do not wrap as intended with the default. Smell: `flexWrap: 'wrap'` with no `alignItems`. Source: https://reactnative.dev/docs/layout-props#flexwrap
- **Space siblings with `gap`**: "It is a shorthand for `rowGap` and `columnGap`." - replace per-child margins and last-child exceptions. Why: one container property stays correct as children are added, removed or wrapped. Smell: `marginRight: 8` on each child plus a special case for the last one. Source: https://reactnative.dev/docs/layout-props#gap
- **Know which ancestor an absolute element is positioned against**: "These values will position the element relative to its containing block." - that is the nearest ancestor with a `position` other than `static` or with a `transform`. Why: adding a `transform` to an ancestor changes where its absolute descendants land. Smell: an absolute badge that moves after a `transform` is added to a wrapper. Source: https://reactnative.dev/docs/flexbox#the-containing-block
- **Prefer document order to `zIndex`**: "Normally, you don't use `zIndex`." - render the element that should be on top later. Why: "Components render according to their order in the document tree, so later components draw over earlier ones." Smell: `zIndex: 999` on an element that could be moved to the end of its parent. Source: https://reactnative.dev/docs/layout-props#zindex
- **Apply `zIndex` between siblings on iOS**: "On iOS, `zIndex` may require `View`s to be siblings of each other for it to work as expected." - lift the elements to a common parent before relying on `zIndex`. Why: stacking across different parents behaves differently per platform. Smell: `zIndex` on a deeply nested dropdown expected to cover a view in another subtree. Source: https://reactnative.dev/docs/layout-props#zindex
- **Use `start` and `end` properties for layouts that support RTL**: "When the direction is `ltr`, `start` is equivalent to `left`. When the direction is `rtl`, `start` is equivalent to `right`." - prefer `marginStart`, `paddingEnd`, `start` and `end` to the left and right forms. Why: left and right properties do not mirror in right-to-left locales. Smell: `marginLeft` and `left` in an app that ships Arabic or Hebrew. Source: https://reactnative.dev/docs/layout-props#start
- **Clip rounded containers with `overflow: 'hidden'`**: "If the rounded border is not visible, try applying `overflow: 'hidden'` as well." - add it when children must follow the rounded corners. Why: children draw over the corners, because `overflow` defaults to visible. Smell: a card with `borderRadius` whose image child shows square corners. Source: https://reactnative.dev/docs/view-style-props#borderradius

## Colours, shadows and effects

- **Write named colours in lowercase**: "React Native only supports lowercase color names. Uppercase color names are not supported." - use `'red'`, not `'Red'`. Why: a capitalised name is not recognised as a colour. Smell: `color: 'White'` or `'DarkGray'`. Source: https://reactnative.dev/docs/colors#named-colors
- **Do not expect the `shadow` props to draw a shadow on Android**: "only `shadowColor` works on both Android and iOS, all other `shadow` props only work on iOS" - use `boxShadow` or `elevation` for Android. Why: `shadowOffset`, `shadowOpacity` and `shadowRadius` are ignored there. Smell: a card style with the four shadow props and nothing for Android. Source: https://reactnative.dev/docs/shadow-props
- **Check platform floors before using `boxShadow`** (New Architecture only): "Outset shadows are only supported on Android 9+. Inset shadows are only supported on Android 10+." - provide a fallback for lower Android versions. Why: the shadow is absent on unsupported versions. Smell: an inset `boxShadow` as the only visual separation of a field. Source: https://reactnative.dev/docs/view-style-props#boxshadow
- **Remember `elevation` changes stacking as well as shadow** (Android only): "This adds a drop shadow to the item and affects z-order for overlapping views." - compare the stacking of overlapping elements on Android after adding it. Why: an elevated card can cover a sibling that renders above it on iOS. Smell: a floating label hidden behind an elevated input on Android only. Source: https://reactnative.dev/docs/view-style-props#elevation-android
- **Expect `filter` to clip descendants** (New Architecture only): "`filter` implies `overflow: hidden`, so descendants will be clipped to fit the bounds of the `View`." - do not place overflowing badges or shadows inside a filtered view. Why: anything outside the bounds disappears. Smell: a `filter` on a container whose child uses negative offsets to hang outside it. Source: https://reactnative.dev/docs/view-style-props#filter
- **Use only `brightness` and `opacity` filters on iOS**: "these are the only two filter functions available on iOS" - `blur`, `contrast`, `dropShadow`, `grayscale`, `hueRotate`, `invert`, `sepia` and `saturate` are Android only. Why: the effect is missing on iOS. Smell: `filter: [{grayscale: 1}]` for a disabled state with no iOS alternative. Source: https://reactnative.dev/docs/view-style-props#filter

## Platform-specific code

- **Use `Platform.OS` or `Platform.select` for small differences**: "Use this option when only small parts of a component are platform-specific." - keep one file when a few values differ. Why: duplicating a whole component for one style difference doubles maintenance. Smell: `Card.ios.tsx` and `Card.android.tsx` that differ by one padding value. Source: https://reactnative.dev/docs/platform-specific-code#platform-module
- **Split heavily branched components into platform files**: "When your platform-specific code is more complex, you should consider splitting the code out into separate files." - use `.ios.` and `.android.` extensions and import without the extension. Why: "React Native will automatically pick up the right file based on the running platform." Smell: a component with `Platform.OS` checks in most of its render branches. Source: https://reactnative.dev/docs/platform-specific-code#platform-specific-extensions
- **Give `Platform.select` a `default` or `native` key**: "If those are not specified, `native` key will be used and then the `default` key." - cover platforms beyond the two named ones. Why: with only `ios` and `android` keys, any other platform receives `undefined`. Smell: `Platform.select({ios: 12, android: 8})` in code that also runs on web. Source: https://reactnative.dev/docs/platform#select
- **Compare `Platform.Version` to API levels on Android**: "`Version` is set to the Android API version not the Android OS version" - write `>= 33`, not `>= 13`. Why: comparing against the marketing version is always true or always false. Smell: `Platform.Version >= 12` in an Android branch. Source: https://reactnative.dev/docs/platform-specific-code#detecting-the-android-version-android
- **Parse `Platform.Version` before comparing on iOS**: "which is a string with the current version of the operating system" - use `parseInt(Platform.Version, 10)` for the major version. Why: comparing strings orders versions alphabetically. Smell: `Platform.Version >= '17'` or arithmetic on the raw value. Source: https://reactnative.dev/docs/platform-specific-code#detecting-the-ios-version-ios

## Keyboard

- **Always set `behavior` on `KeyboardAvoidingView`**: "On both iOS and Android, setting `behavior` is recommended." - choose the value per platform. Why: "Android and iOS both interact with this prop differently." Smell: `<KeyboardAvoidingView>` with no `behavior`, or one value used on both platforms without testing. Source: https://reactnative.dev/docs/keyboardavoidingview#behavior
- **Set `keyboardVerticalOffset` when the view does not start at the top of the screen**: "This is the distance between the top of the user screen and the react native view, may be non-zero in some use cases." - pass the header height when a navigation header sits above the view. Why: with a zero offset the content stays partly covered by the keyboard. Smell: a `KeyboardAvoidingView` under a header whose last input is still hidden. Source: https://reactnative.dev/docs/keyboardavoidingview#keyboardverticaloffset
- **Listen to the `Did` keyboard events in cross-platform code**: "Only `keyboardDidShow` and `keyboardDidHide` events are available on Android." - use `keyboardWillShow` and `keyboardWillHide` only in an iOS branch. Why: the `Will` listeners never fire on Android. Smell: `Keyboard.addListener('keyboardWillShow', ...)` with no Android counterpart. Source: https://reactnative.dev/docs/keyboard#addlistener
- **Do not depend on keyboard events with `adjustResize` on Android 10 or below**: "The events will not be fired when using Android 10 or below if your activity has `android:windowSoftInputMode` set to `adjustResize` or `adjustNothing`." - derive layout from the resized window instead. Why: logic tied to these events never runs on those devices. Smell: a footer shown and hidden purely from keyboard events in an app that supports Android 10. Source: https://reactnative.dev/docs/keyboard#addlistener
- **Keep the subscription returned by `Keyboard.addListener`**: "This function then returns the reference to the listener." - store it and call its `remove` method in the cleanup. Why: a listener that is never removed keeps firing after the screen unmounts. Smell: `Keyboard.addListener(...)` in an effect with no returned cleanup. Source: https://reactnative.dev/docs/keyboard#addlistener

## Safe areas

- **Replace the core `SafeAreaView`** (deprecated): "Use react-native-safe-area-context instead." - import `SafeAreaView` or `useSafeAreaInsets` from that library. Why: the core component "is currently only applicable to iOS devices with iOS version 11 or later", so Android gets no insets. Smell: `import {SafeAreaView} from 'react-native'`. Source: https://reactnative.dev/docs/safeareaview
- **Do not put padding on the core `SafeAreaView`**: "padding rules in styles applied to a `SafeAreaView` will be ignored and can cause different results depending on the platform" - put the padding on an inner `View`. Why: the component implements its insets with padding and overwrites yours. Smell: `<SafeAreaView style={{padding: 16}}>` from `react-native`. Source: https://reactnative.dev/docs/safeareaview#props
- **Wrap screen content in the library `SafeAreaView`**: "It is a regular `<View>` with the safe area insets applied as extra padding or margin." - use it in place of the root `View` of a screen that has no stack header; on a stack screen with a header it adds a second top inset, so leave the top edge to the header. Why: without a safe area, content is "overlapped by notches, status bars, home indicators, and other interface elements". Smell: a screen whose root is a plain `View` with a hard-coded `paddingTop: 44`. Source: https://docs.expo.dev/develop/user-interface/safe-areas/#use-react-native-safe-area-context-library
- **Add `SafeAreaProvider` at the root when Expo Router is not installed**: "to the root component file (such as App.tsx) before using `SafeAreaView` in your screen component" - the Expo docs require this for templates without Expo Router. Why: the library's components and hooks read their insets from the provider. Smell: `useSafeAreaInsets` used in a project with no `SafeAreaProvider` and no Expo Router. Source: https://docs.expo.dev/develop/user-interface/safe-areas/#usage
- **Use `useSafeAreaInsets` for per-edge control**: "It provides direct access to the safe area insets, allowing you to apply padding for each edge of the `<View>` using an inset from this hook." - apply `insets.top` or `insets.bottom` only where the design needs it. Why: device-specific constants are wrong on the next device shape. Smell: `paddingBottom: Platform.OS === 'ios' ? 34 : 0`. Source: https://docs.expo.dev/develop/user-interface/safe-areas/#alternate-usesafeareainsets-hook
- **Use CSS `env()` for safe areas on web**: "On web, use CSS `env(safe-area-inset-*)` values for safe-area spacing." - keep the library for Android and iOS routes. Why: "The browser updates this spacing without a React state update." Smell: `useSafeAreaInsets` driving padding in a web-specific route. Source: https://docs.expo.dev/develop/user-interface/safe-areas/#usage-with-web
- **Do not add a second `SafeAreaProvider` on web with Expo Router** (Expo SDK 58 and later): "Do not add another `SafeAreaProvider` to restore these measurements." - Expo Router disables automatic safe-area measurement on web from SDK 58. Why: "Its updates can interrupt hydration and discard pending streamed content, even if you provide `initialMetrics`." Smell: a `SafeAreaProvider` added inside a layout after web insets started returning zero. Source: https://docs.expo.dev/develop/user-interface/safe-areas/#usage-with-web

## Modal

- **Handle `onRequestClose` on every `Modal`**: "The `onRequestClose` callback is called when the user taps the hardware back button on Android or the menu button on Apple TV." - close the modal there, or the Android back button does nothing. Why: "be aware that `BackHandler` events will not be emitted as long as the modal is open". Smell: a `Modal` with `visible` and no `onRequestClose`, or back handling done through `BackHandler` while a modal is open. Source: https://reactnative.dev/docs/modal#onrequestclose
- **Implement `onRequestClose` when enabling `allowSwipeDismissal`** (iOS only): "This requires you to implement the `onRequestClose` prop to handle the dismissal." - set `visible` to false in the handler. Why: state stays out of sync with what the user sees after the swipe. Smell: `allowSwipeDismissal` with no `onRequestClose`. Source: https://reactnative.dev/docs/modal#allowswipedismissal-ios
- **Do not run cross-platform logic in `onDismiss`** (iOS only): "The `onDismiss` prop allows passing a function that will be called once the modal has been dismissed." - the prop is marked iOS, so trigger shared follow-up work from the close handler. Why: the follow-up never runs on Android. Smell: navigation or data refresh placed only in `onDismiss`. Source: https://reactnative.dev/docs/modal#ondismiss-ios

## StatusBar, ActivityIndicator and Switch

- **Do not mix the static `StatusBar` API with the component for one property**: "not recommended to use the static API and the component for the same prop" - choose `StatusBar.setBarStyle` or `<StatusBar barStyle>` for a given property, not both. Why: "any value set by the static API will get overridden by the one set by the component in the next render". Smell: `StatusBar.setHidden(true)` in an effect while a mounted `<StatusBar hidden={false} />` exists. Source: https://reactnative.dev/docs/statusbar#imperative-api
- **Do not use `StatusBar.currentHeight` as a cross-platform inset** (Android only): "The height of the status bar, which includes the notch height, if present." - the constant is marked Android; use safe area insets for top padding. Why: on iOS there is no value, so the padding collapses. Smell: `paddingTop: StatusBar.currentHeight` on a shared header. Source: https://reactnative.dev/docs/statusbar#currentheight-android
- **Update `value` from `onValueChange` on every `Switch`**: "If the `value` prop is not updated, the component will continue to render the supplied `value` prop instead of the expected result of any user actions." - it is a controlled component. Why: the switch snaps back and looks broken. Smell: a `Switch` with `value` and no `onValueChange`, or a handler that never updates the source of `value`. Source: https://reactnative.dev/docs/switch
- **Set `ios_backgroundColor` for the off state on iOS** (iOS only): "When the switch value is `false`, the track shrinks into the border." - `trackColor.false` alone does not fill the background that the shrunken track exposes. Why: the off state shows the default colour behind the track. Smell: a custom `trackColor` with a `false` colour and no `ios_backgroundColor`. Source: https://reactnative.dev/docs/switch#trackcolor

## Colour scheme

- **Read the colour scheme with `useColorScheme`**: "Recommended: Use the `useColorScheme` hook." - call it in components rather than `Appearance.getColorScheme()`. Why: the hook "provides and subscribes to color scheme updates", so the component re-renders when the scheme changes. Smell: `Appearance.getColorScheme()` called inside a component body. Source: https://reactnative.dev/docs/appearance
- **Do not cache the colour scheme**: "should try to call this function on every render, rather than caching the value" - never read it once at module scope or store it in a `StyleSheet`. Why: the scheme can change at runtime, for example on a "scheduled color scheme change at sunrise or sunset". Smell: `const isDark = Appearance.getColorScheme() === 'dark'` at the top of a file. Source: https://reactnative.dev/docs/appearance
- **Handle a `null` colour scheme**: "`null`: May be returned if the native Appearance module is not available." - fall back to a default theme. Why: indexing a theme map with `null` yields `undefined` styles. Smell: `themes[useColorScheme()]` with no fallback. Source: https://reactnative.dev/docs/usecolorscheme#return-values
- **Pass `'auto'` to `setColorScheme` to follow the system** (`'unspecified'` deprecated): "Passing `'auto'` removes any override, restoring the system preference." - replace `'unspecified'`, which the docs list as deprecated. Why: the deprecated value may be removed. Smell: `Appearance.setColorScheme('unspecified')`. Source: https://reactnative.dev/docs/appearance#setcolorscheme
