# CSS Layout Rules (MDN)

Extracted 2026-11-08 from the mdn/content repository. Baseline statuses from the web-features dataset on the same date.

## Flexbox

- **Reach for flexbox when the layout is one-dimensional**: "Flexbox is generally the right CSS layout solution when you want to lay out a collection of items in one dimension or control the spacing between items." Why: flexbox distributes space along a single axis and treats each wrapped line as its own container, so it cannot line items up across rows. Smell: `display: flex; flex-wrap: wrap` on a card grid whose rows are expected to line up with each other. Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Flexible_box_layout/Use_cases#why_choose_flexbox
- **Drop floats and vertical-align once a parent is a flex container**: "if an item was floated or cleared and then becomes a flex item due to the parent having `display: flex` applied, the floating and clearing will no longer happen", and `vertical-align` "will no longer affect the item and you can use the alignment properties of flexbox instead." Why: a flex container "establishes a new flex formatting context, so floats will not intrude and the containers' margins will not collapse." Smell: `float: left` or `vertical-align: middle` on `.toolbar > *` where `.toolbar` is `display: flex`. Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Flexible_box_layout/Relationship_with_other_layout_methods#flexbox_and_other_layout_methods
- **Use `flex: 1` for equal columns, not widths on the items**: "To create three equally-sized items, even if the original elements have different sizes, set the `flex-basis` component to `0`", which is what `flex: 1` does. Why: "for the purpose of space distribution calculation, we are setting the size of each item to `0`. This means all the space is available for distribution." Smell: `width: 100%`, `width: 33.333%` or `flex-basis: 33%` on children of a flex container that should simply share the row. Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Flexible_box_layout/Controlling_flex_item_ratios#combining_flex-grow_and_flex-basis
- **Switch to grid when you start forcing flex items into columns**: "when you catch yourself adding widths to flex items in this way or adding empty flex items to take up space, it is a good indication you may want to switch to CSS grid layout for that component." Why: "Flexbox-based layouts can be forced to line up as grid systems, but that is not the intended purpose of flexbox." Smell: `flex: 0 0 25%` on every item plus `flex-wrap: wrap`, or empty `<div class="spacer">` elements. Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Flexible_box_layout/Wrapping_items#how_do_flexbox-based_grid_systems_work
- **Put alignment properties on the flex container**: "A key feature of flexbox is the ability to align and justify items on the main- and cross-axes, and to distribute space between flex items. Note that these properties are set on the flex container, not on the items themselves." Why: the container owns the axes the items are aligned along. Smell: `justify-content: center` or `align-items: center` on an element that is not `display: flex` or `display: grid`, or on an individual flex item. Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Flexible_box_layout/Basic_concepts#alignment_justification_and_distribution_of_free_space_between_items
- **Do not use `justify-items` or `justify-self` on flex items**: "In flexbox `justify-self` or `justify-items` do not apply, as on the main axis items are treated as a group." Why: the main axis is distributed with `justify-content` for the whole group, so a per-item justification has nothing to act on. Smell: `justify-self: end` on a flex child, or `place-items: center` on a flex container expected to centre horizontally. Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/place-items#placing_items_in_a_flex_container
- **Centre with alignment properties, not absolute positioning**: "Flexbox provides several properties to control alignment and spacing, with `align-items` and `justify-content` being fundamental for centering elements." Why: the container resolves the centring from its own size, so no offsets or transform maths are needed and the child stays in flow. Smell: `position: absolute; top: 50%; left: 50%; transform: translate(-50%, -50%)` used only to centre a child. Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Flexible_box_layout/Aligning_items#using_alignment_in_flexbox
- **Centre in block layout with `align-content` when no flex is needed**: "With CSS box alignment properties, you can vertically center an element inside another without flexbox. In the example above, try removing the flex properties from the box and adding `align-content: center`. Then add `margin: auto` to the element you want to horizontally center." Why: a flex container only to centre one child adds a formatting context you do not need. Smell: `display: flex; align-items: center; justify-content: center` wrapped around a single block of text. Baseline: Widely (since 2026-10). Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Flexible_box_layout/Use_cases#center_item
- **Pin a card footer with a column flex container and `flex: 1`**: "We make the card a flex container, with `flex-direction: column`. We then set the content area to `flex: 1`" Why: "As this is the only item that can grow, it takes up all available space in the flex container and pushes the footer to the bottom." Smell: a fixed `height` on cards, or `position: absolute; bottom: 0` on the footer with matching `padding-bottom` on the card. Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Flexible_box_layout/Use_cases#card_layout_pushing_footer_down
- **Set `min-width: 0` when a flex item must shrink past its content**: "By default flex items don't shrink below their `min-content` size. To change this, set the item's `min-width` or `min-height`." Why: the automatic minimum size of a flex item is its `min-content` size, so one unbreakable word or URL stops the item from shrinking and pushes its siblings out. Smell: `overflow: hidden` on a flex container to hide a long word or URL that pushes siblings out. Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/flex#description

## Grid

- **Choose grid when rows and columns both matter**: "Do we only need to control the layout by row or column? If yes, use flexbox." and "Do we need to control the layout by row and column? If yes, use grid layout." Why: "when you wrap flex items, each new row (or column when working by column) is an independent flex line in the flex container." Smell: a wrapped flex container whose last row stretches differently from the rows above. Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Grid_layout/Relationship_with_other_layout_methods#one-dimensional_versus_two-dimensional_layout
- **Size flexible tracks with `fr`, not percentages**: "The `fr` unit represents a fraction of the available space in the grid container." Why: "Any space used by gaps will be accounted for before space is assigned to the flexible length `fr` tracks", so percentages plus `gap` overflow while `fr` tracks do not. Smell: `grid-template-columns: 33.33% 33.33% 33.33%` or `repeat(3, 33%)` alongside a `gap`. Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Grid_layout/Basic_concepts#the_fr_unit
- **Let `repeat(auto-fit, minmax())` decide the column count**: "If we make the window smaller or wider, the number of column tracks changes – without media queries adding breakpoints and without needing to redefine the grid." Why: "We create a grid with a flexible number of flexible columns. We want them to be at least 200 pixels wide and share any available remaining space equally". Smell: a breakpoint ladder of `grid-template-columns: repeat(2, 1fr)`, `repeat(3, 1fr)`, `repeat(4, 1fr)`. Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Grid_layout/Common_grid_layouts#a_product_listing_with_auto-placement
- **Pick `auto-fit` when items should stretch into empty tracks**: "The `auto-fit` value behaves the same as `auto-fill`, except that after placing the grid items any empty repeated tracks are collapsed." Why: "A collapsed track is treated as having a single fixed track sizing function of `0px`, and the gutters on either side of it collapse", so the remaining `1fr` tracks grow. Smell: `repeat(auto-fill, minmax(200px, 1fr))` with a few items leaving a half-empty row that was meant to fill. Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/repeat#auto-fit_versus_auto-fill
- **Give rows a `minmax()` floor rather than a fixed height**: "By setting `grid-auto-rows: minmax(100px, auto);`, automatically created rows will be a minimum of `100px` tall, and have a maximum of `auto`." Why: "Setting `auto` as the maximum value allows the track to grow to accommodate its content". Smell: `grid-auto-rows: 100px` or `height: 100px` on grid items that hold variable text. Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Grid_layout/Basic_concepts#track_sizing_and_minmax
- **Describe component layouts with `grid-template-areas`**: "Using `grid-template-areas` can be especially nice as it allows you to visualize what your element looks like in the code." Why: "Using this method we do not need to specify anything at all on the individual grid items, everything happens on our grid container." Smell: `grid-column: 1 / 3; grid-row: 2 / 3` scattered across several child selectors for a fixed page shell. Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Grid_layout/Grid_template_areas#using_grid-template-areas_for_ui_elements
- **Name areas once, outside media queries**: "When doing this, define the names for your areas outside of any media queries. That way the content area would always be called `main` no matter where on the grid it is placed." Why: "As our layout is now contained in one part of the CSS, we can make changes for different breakpoints in one location in our codebase." Smell: `grid-area: main` repeated inside every `@media` block. Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Grid_layout/Grid_template_areas#redefining_the_grid_using_media_queries
- **Use `subgrid` to align nested items with the parent tracks**: "If you set the value `subgrid` on `grid-template-columns`, `grid-template-rows` or both, instead of creating a new track listing, the nested grid uses the tracks defined on the parent." Why: nested grids "are independent of the parent grid and of each other, meaning that they do not take their track sizing from the parent grid. This makes it difficult to line nested grid items up with the main grid." Smell: `grid-template-columns: repeat(3, 1fr)` copied from the parent onto a child grid, or `display: contents` used only to reach the parent tracks. Baseline: Widely (since 2026-03). Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Grid_layout/Subgrid#introduction_to_subgrid
- **Drop row wrapper markup**: "We don't need to add any markup to create a row. CSS framework grid systems often did this to stop elements popping up into the row above for browsers that don't support CSS grid layout. However, this point is now moot". Why: "CSS grids allow us to place items into rows, with no danger of them rising up into the row above if it is left empty." Smell: `<div class="row">` wrappers with `.col-4` children inside a `display: grid` parent. Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Grid_layout/Common_grid_layouts#a_flexible_12-column_layout
- **Use `grid-auto-flow: dense` only for unordered content**: "Take care when doing this as it can cause items to be taken out of their logical source order. You should only do this if your items do not have a set order." Why: "the tab order following the source and not your reordered display." Smell: `grid-auto-flow: dense` on a form, a list of steps, or a news feed. Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Grid_layout/Common_grid_layouts#preventing_gaps_with_the_dense_keyword
- **Reorder visually only, never to fix the source**: "Authors must use `order` and the grid-placement properties only for visual, not logical, reordering of content. Style sheets that use these features to perform logical reordering are non-conforming." Why: "The `order` property and grid placement do not affect ordering in non-visual media (such as speech)." Smell: `order: -1` on a heading or call to action so it reads first on screen while staying last in the HTML. Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Grid_layout/Accessibility#re-ordering_content_in_css_grid_layout
- **Keep `display: contents` away from semantic elements**: "Some browsers incorrectly remove some elements with `display: contents` from the accessibility tree (but descendants will remain), removing those elements' semantics while maintaining their child content." Why: "This means the element itself may not be announced by screen readers." Smell: `ul, ol, table, button { display: contents }` so that children become grid or flex items. Baseline: Limited. Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Flexible_box_layout/Relationship_with_other_layout_methods#flexbox_and_display_contents

## Container queries

- **Size components with container queries, not viewport breakpoints**: "Container queries are an alternative to media queries, which apply styles to elements based on viewport size or other device characteristics." Why: "Using container queries, the card can be reused in multiple areas of a page without needing to know specifically where it will be placed each time." Smell: `@media (min-width: 768px) { .card { grid-template-columns: 1fr 2fr } }` inside a component stylesheet. Baseline: Widely (since 2025-08). Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Containment/Container_queries#using_container_size_queries
- **Declare `container-type: inline-size` on the parent you query**: "To use container size queries, you need to declare a containment context on an element so that the browser knows you might want to query the dimensions of this container later." Why: `inline-size` "Applies layout, style, and inline-size containment to the element." while leaving the block size free to follow content. Smell: an `@container (width > 30rem)` rule with no ancestor carrying `container-type` or `container`. Baseline: Widely (since 2025-08). Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Containment/Container_queries#using_container_size_queries
- **Avoid `container-type: size` unless the block size is set elsewhere**: "size containment means that the size of the size-contained element's children cannot affect the size of the element itself — its size is computed as if it had no children." Why: "If no size is set, the element risks being zero-sized in most cases." Smell: `container-type: size` on a card or section whose height comes from its text. Baseline: Widely (since 2024-09). Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Containment/Using#size_containment
- **Name containers when more than one ancestor is a container**: "A container name makes the container condition more specific — it is evaluated only against elements that have that name set in the `container-name` property." Why: "Without a `<container-name>`, the query matches only the nearest container ancestor". Smell: nested unnamed `container-type: inline-size` wrappers with `@container (min-width: ...)` rules that bind to whichever is closest. Baseline: Widely (since 2025-08). Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Containment/Container_size_and_style_queries#naming_containers
- **Use `cqi` and `cqb` for sizes inside a component**: "Components that use units of length relative to their container are more flexible to use in different containers without having to recalculate concrete length values." Why: "If no eligible container is available for the query, the container query length unit defaults to the small viewport unit for that axis (`sv*`)." Smell: `font-size: 4vw` or `padding: 2vw` inside a component that can sit in a sidebar. Baseline: not listed. Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Containment/Container_queries#container_query_length_units
- **Write viewport queries with range syntax**: "With media query range features, you can either use the inclusive `min-` and `max-` prefixes or the more concise range syntax operators `<=` and `>=`." Why: "The range comparisons above are inclusive. To exclude the comparison value, use `<` and/or `>`." so overlapping breakpoints become explicit. Smell: `@media (min-width: 768px) and (max-width: 1023px)` instead of `@media (768px <= width < 1024px)`. Baseline: Widely (since 2025-09). Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Media_queries/Using#targeting_media_features

## Intrinsic sizing

- **Cap a fluid value with `min()`**: "We're using `min()` to set a maximum line length: it can go under `1000px`, but won't go over." Why: "This is helpful because long lines are harder to read, so we often want to limit how long a line can be." Smell: `width: 90%` at one breakpoint and `width: 1000px` at another. Baseline: Widely (since 2023-01). Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/clamp#min_max_and_clamp_comparison
- **Floor a fluid value with `max()`**: "Think of the `max()` function as finding the minimum value allowed for a property." Why: "The font-size will at minimum be 2rems, or twice the default size of font for the page. This ensures that it is legible and accessible." Smell: `font-size: 3vw` with a media query that resets it to `1rem` on small screens. Baseline: Widely (since 2023-01). Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/max#setting_a_minimum_size_for_a_font
- **Use `clamp()` for one value that scales between two bounds**: using `clamp()` "allows you to set a font-size that grows with the size of the viewport, but doesn't go below a minimum font-size or above a maximum font-size. It has the same effect as the code in Fluid Typography but in one line, and without the use of media queries." Why: "`clamp(MIN, VAL, MAX)` is resolved as `max(MIN, min(VAL, MAX))`." Smell: three or more breakpoints each setting a different fixed `padding-inline` or heading size. Baseline: Widely (since 2023-01). Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/clamp
- **Keep a `clamp()` text maximum relative and at least double the minimum**: "When `clamp()` is used for controlling text size, make sure that the maximum allowed value is a relative length unit that is no less than twice the minimum allowed value". Why: "This helps to ensure that text size can scale to at least 200% if the page is zoomed." Smell: `font-size: clamp(1rem, 2vw, 1.25rem)` or `clamp(16px, 2vw, 24px)`. Baseline: Widely (since 2023-01). Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/clamp#accessibility
- **Combine units with `calc()` instead of scripting the size**: "The `calc()` function lets you specify CSS property values using addition, subtraction, multiplication, and division. It is often used to combine two CSS values that have different units, such as `%` and `px`." Why: "This solution is often simpler to implement and faster for the browser to execute than using JavaScript." Smell: `element.style.height = window.innerHeight - nav.offsetHeight + 'px'` in a resize handler. Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Values_and_units/Using_math_functions#calc_basic_math_operations
- **Set `box-sizing: border-box` before sizing boxes**: "It is often useful to set `box-sizing` to `border-box` to lay out elements. This makes dealing with the sizes of elements much easier, and generally eliminates a number of pitfalls you can stumble on while laying out your content." Why: with `content-box`, "if you have four boxes with `width: 25%;`, if any has left or right padding or a left or right border, they will not by default fit on one line within the constraints of the parent container." Smell: `width: calc(25% - 2rem)` to compensate for padding, or a `width: 100%` input that overflows its parent. Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/box-sizing#description

## Logical properties

- **Default to logical properties and values**: "The logical properties defined in this module enable defining properties relative to the content's writing direction, rather than a physical direction. This means content translated into languages with different writing modes will be rendered as intended." Why: "The start of a line is not always the left side of a line. Different writing systems operate in various directions." Smell: `margin-left`, `padding-right`, `border-bottom`, `text-align: left` in component CSS. Baseline: Widely (since 2024-03). Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Logical_properties_and_values
- **Write `inline-size` and `block-size` instead of `width` and `height`**: "If instead of the `width` property, the logical property `inline-size` is used, the component will work the same way no matter which writing mode it is displayed using." Why: a width "is a horizontal measure, a measure tied to the physical and not the logical or flow relative running of the text." Smell: `width: 100%`, `max-width: 60ch`, `min-height: 100vh` in reusable components. Baseline: Widely (since 2024-03). Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Logical_properties_and_values/Basic_concepts#why_are_logical_properties_useful
- **Use the two-value `margin-inline` and `margin-block` shorthands**: "There are shorthands available to target either both the inline sides or both the block sides, `margin-inline` and `margin-block` respectively. Each accepts two values. The first value will apply to the start of that dimension, the second to the end. If only one value is set, it is applied to both." Why: the same page says these shorthands "have no physical equivalent." Smell: `margin-left: auto; margin-right: auto` or `padding-top: 1rem; padding-bottom: 2rem` as separate declarations. Baseline: Widely (since 2024-03). Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Logical_properties_and_values/Margins_borders_padding#margin_shorthands
- **Do not mix logical intent with four-value shorthands**: "Using any four-value shorthand such as `margin`, `padding`, or `border` will currently use the physical versions, so if following the flow of the document is important, use the longhand properties for the time being." Why: "the final decision on how this should be indicated is as yet unresolved". Smell: `margin: 0 1rem 0 0` or `padding: 0 0 0 2rem` next to otherwise logical declarations. Baseline: Widely (since 2024-03). Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Logical_properties_and_values/Margins_borders_padding#indicating_logical_values_for_the_4-value_shorthand_syntax
- **Collapse `top`, `right`, `bottom`, `left` into `inset`**: "The `inset` CSS shorthand property corresponds to the `top`, `right`, `bottom`, and/or `left` properties. It has the same multi-value syntax of the `margin` shorthand." Note that it "does not define logical offsets. It defines physical offsets, regardless of the element's writing mode, directionality, and text orientation"; use `inset-inline` and `inset-block` for flow-relative offsets. Smell: `top: 0; right: 0; bottom: 0; left: 0` on an overlay instead of `inset: 0`. Baseline: not listed (the `inset-*` logical longhands belong to the logical properties group, Widely since 2024-03). Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/inset
- **Push and offset with flow-relative properties in flex and grid**: "Setting physical properties, such as setting auto margins using `margin-right` or `margin-left`, or absolutely positioning items using the `top`, `right`, `bottom`, and `left` offsets, does not honor writing modes." Why: "When displaying a right to left language, such as Arabic, the start of the grid is the top right". Smell: `margin-left: auto` to push a nav item, or `left: 1rem` on a badge, where `margin-inline-start: auto` and `inset-inline-start: 1rem` were meant. Baseline: Widely (since 2024-03). Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Grid_layout/Box_alignment#alignment_and_writing_modes
- **Keep physical properties where the thing is physical**: "While these flow relative mappings may well become the default for many of us, in a design you may well use both physical and logical sizing. You might want some features to always relate to the physical dimensions whatever the writing mode." Why: a shadow cast downward or a bar fixed to the bottom of the screen does not rotate with the writing mode. Smell: `inset-block-end: 0` on a mobile toolbar that must stay at the physical bottom, or `box-shadow` offsets rewritten through logical custom properties. Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Logical_properties_and_values/Sizing

## Spacing and gap

- **Space siblings with `gap` on the container**: "To create gaps or gutters between flex items, use the `gap` property directly on the flex container to create a fixed space between adjacent flex items." Why: "The `gap` property is not the only thing that can add space between items. Margins, padding, `justify-content`, and `align-content` can also increase the size of the gutter, affecting the actual size of the gap." Smell: `.item + .item { margin-left: 1rem }`, `.item:not(:last-child) { margin-right: 1rem }`, or negative margins on the container to cancel edge margins. Baseline: Widely (since 2023-10). Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Flexible_box_layout/Wrapping_items#creating_gutters_between_items
- **Write `gap`, not `grid-gap`**: "Early versions of the CSS grid specification called this property `grid-gap`. To maintain compatibility with legacy websites, browsers accept `grid-gap` as an alias for `gap`." Why: `gap` "sets the gaps (also called gutters) between rows and columns on multi-column, flex, and grid containers." so one name covers every layout. Smell: `grid-gap: 1rem`, `grid-row-gap` or `grid-column-gap` in new code. Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/gap#in_grid_layouts
- **Avoid percentage gaps on auto-sized containers**: "In case of the flex layout, the percentage gap always results in zero value." and in grid "the grid remains 100px high but it overflows due to the percentage gap added later just before rendering." Why: "Percentage gap values are always calculated against the content box size of the container element." which is unknown until laid out. Smell: `gap: 5%` or `row-gap: 10%` on a flex column or grid without a definite block size. Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/gap#percentage_gap_value_and_implicit_container_size
- **Stop parent and child margins collapsing with a formatting context, not a fake border**: "In both cases, creating a new block formatting context on the parent will also prevent its margins from collapsing with its children." Why: a parent's margin collapses with its first child's "unless the parent has a `border-top` , `padding-top` , contains any inline content (such as text), or has clearance applied." Smell: `padding-top: 0.1px` or `border-top: 1px solid transparent` added only to keep a child's `margin-top` inside the box. Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Box_model/Margin_collapsing

## Aspect ratio and viewport units

- **Use `aspect-ratio` instead of the padding-bottom hack**: "While it's possible to define an aspect ratio on non-replaced elements by setting both the dimensions and hiding overflowing content, the CSS `aspect-ratio` property provides explicit aspect ratio support. This means a specific aspect ratio can be set even when you don't know the content or screen sizes." Why: "Setting an asset's aspect ratio prevents loading jank". Smell: `position: relative; padding-bottom: 56.25%; height: 0` with an absolutely positioned child filling it. Baseline: Widely (since 2024-03). Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Box_sizing/Aspect_ratios#defining_aspect_ratios_for_non-replaced_elements
- **Leave one dimension automatic for `aspect-ratio` to apply**: "At least one of the box's sizes needs to be automatic in order for `aspect-ratio` to have any effect. If neither the width nor height is an automatic size, then the provided aspect ratio has no effect on the box's preferred sizes." Smell: `aspect-ratio: 16 / 9; width: 100%; height: 200px` in the same rule. Baseline: Widely (since 2024-03). Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/aspect-ratio#description
- **Fit images with `object-fit` rather than forcing both dimensions**: "Only when you provide sizes for both dimensions is there a risk of distorting the replaced element." and "To fit a replaced element to the dimensions of its container while maintaining its intrinsic aspect ratio, set the `object-fit` property value to `cover` or `contain`." Smell: `img { width: 100%; height: 200px }` with no `object-fit`. Baseline: Widely (since 2022-07). Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Box_sizing/Aspect_ratios#fitting_replaced_elements_within_their_containers
- **Make square tiles with `aspect-ratio: 1`, not fixed rows**: "By setting an aspect ratio on the items, we can ensure when the grid items are laid out, each grid item will be as tall as it is wide, creating square grid items regardless of the container's dimensions." Why: with `auto-fill` "the width of each item becomes uncertain. This makes it challenging to determine the appropriate height for creating square items." Smell: `grid-auto-rows: 200px` paired with `minmax(200px, 1fr)` columns, or JS that copies `offsetWidth` into `height`. Baseline: Widely (since 2024-03). Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Box_sizing/Aspect_ratios#making_grid_cells_square
- **Use small or dynamic viewport units for full-height layouts**: "the small viewport-percentage units are "safer" to use in general, but might not produce the most attractive layout after a user starts interacting with the page." Why: "Currently, all default viewport units (`vh`, `vw`, etc.) are equivalent to their large viewport counterparts (`lvh`, `lvw`, etc.)." so `100vh` is taller than the visible area while mobile toolbars are shown. Use `svh` by default and keep `dvh` for the one box that must track the visible viewport, because dynamic units "can cause the content to resize while a user is scrolling a page. This can lead to degradation of the user interface and cause a performance hit." Smell: `height: 100vh` or `min-height: 100vh` on a hero, app shell or modal, or `dvh` on every section of a long page. Baseline: Widely (since 2025-06). Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/length#relative_length_units_based_on_viewport

## Formatting contexts and overflow

- **Keep `float` for wrapping text around media**: `float` "places an element on the left or right side of its container, allowing text and inline elements to wrap around it." Why: "The element is removed from the normal flow of the page", so floats cannot align or size siblings the way flex and grid do. Smell: `float: left; width: 50%` on columns, sidebars or card lists. Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/float
- **Replace clearfix with `display: flow-root`**: "If an element contains only floated elements, its height collapses to nothing. If you want it to always be able to resize, so that it contains floating elements inside it, set the value of the element's `display` property to `flow-root`." Why: `flow-root` creates the block formatting context directly, without the pseudo-element boilerplate or the overflow side effects of other techniques. Smell: `.clearfix::after { content: ""; display: table; clear: both }` or an empty `<div style="clear: both">`. Baseline: Widely (since 2022-07). Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/clear#description
- **Do not use `overflow` to create a formatting context**: "The problem with using `overflow` to create a new BFC is that the `overflow` property is meant for telling the browser how you want to deal with overflowing content. There are some occasions in which you will find you get unwanted scrollbars or clipped shadows when you use this property purely to create a BFC." Why: "it is potentially not readable for a future developer, as it might not be obvious why you used `overflow` for this purpose." Smell: `overflow: hidden` or `overflow: auto` on a wrapper that never has overflowing content. Baseline: Widely (since 2022-07). Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Display/Block_formatting_context#contain_internal_floats
- **Reserve scrollbar space with `scrollbar-gutter: stable`**: `scrollbar-gutter` "allows authors to reserve space for the scrollbar, preventing unwanted layout changes as the content grows while also avoiding unnecessary visuals when scrolling isn't needed." Why: with `stable`, "the gutter will be present if `overflow` is `auto`, `scroll`, or `hidden` even if the box is not overflowing." Smell: `overflow-y: scroll` only to keep a scrollbar track visible, or `padding-right: 17px` to fake the gutter. Baseline: Newly (since 2024-12). Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/scrollbar-gutter
- **Use `both-edges` to keep centred content centred**: "Add symmetric spacing to both sides of the box so the content is centered" with `scrollbar-gutter: stable both-edges`. Why: "If a gutter would be present on one of the inline start/end edges of the box, another will be present on the opposite edge as well." Smell: `margin-inline-start: 17px` or asymmetric padding compensating for a scrollbar beside centred text. Baseline: Newly (since 2024-12). Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/scrollbar-gutter#example_2

## Rendering cost

- **Apply `contain: content` to independent sections**: "Using `contain: content` turns on `layout`, `paint`, and `style` containment. As it omits `size`, it is a safe value to apply widely." Why: "When additional articles are appended at the end of the page, the browser does not need to recalculate layout or repaint the preceding content". Smell: `contain: strict` on an article or card whose height depends on its content. Baseline: Widely (since 2024-09). Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Containment/Using#special_values
- **Pair `contain: size` with `contain-intrinsic-size`**: "If you set `contain: size` on an element, you need to specify the size of the element using `contain-intrinsic-size`, or the longhand properties `contain-intrinsic-width` and `contain-intrinsic-height`, in that order. If no size is set, the element risks being zero-sized in most cases." Smell: `contain: size` or `contain: strict` with no `contain-intrinsic-size` and no explicit `block-size`. Baseline: Widely (since 2026-03). Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Containment/Using#size_containment
- **Skip offscreen rendering with `content-visibility: auto`**: "When you have a lot of content that would benefit from heavy containment that will often be offscreen — for example if all your blog posts are viewable on the blog home pages as an infinitely scrollable blog — `content-visibility: auto` can be used to apply all of the containments at once." Why: "It enables the user agent to skip an element's rendering work (including layout and painting) until it is needed — which makes the initial page load much faster." Smell: a long feed of `<section>` or `<article>` elements with no containment, or a JS virtual list for content that only needs to render lazily. Baseline: Newly (since 2025-09). Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Containment/Using#content-visibility
- **Give `content-visibility: auto` a `contain-intrinsic-size: auto <length>` placeholder**: "The `auto <length>` value allows the size of the element to be stored if the element is ever "normally rendered" (with its child elements), and then used instead of the specified length when the element is skipping its contents." Why: "This allows offscreen elements with `content-visibility: auto` to benefit from size containment without developers having to be as precise in their estimates of element size." Smell: `content-visibility: auto` with no `contain-intrinsic-size`, so the scrollbar jumps as sections render. Baseline: Widely (since 2026-03). Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/contain-intrinsic-size#description
- **Toggle heavy content with `content-visibility: hidden` instead of `display: none`**: "Using `content-visibility: hidden;` instead of `display: none;` preserves the rendering state of content when hidden and rendering is faster." Why: with `hidden`, "The skipped contents must not be accessible to user-agent features, such as find-in-page, tab-order navigation, etc., nor be selectable or focusable. This is similar to giving the contents `display: none`." Smell: `display: none` toggled on large panels or tabs that are shown again moments later. Baseline: Newly (since 2025-09). Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/content-visibility#using_hidden_to_manage_visibility
